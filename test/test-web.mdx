Web call testing allows you to conduct real-time voice conversations with your agent directly through your browser. Unlike text-based [simulation testing](/test/llm-simulation-testing), web calls stream live synthesized audio, allowing you to audit round-trip latency, turn-taking dynamics, conversational pacing, and speech barge-in responsiveness before connecting to public telephony. You can test draft configurations immediately without publishing or provisioning phone numbers.

## What is web call testing?

**Web call testing** allows developers to conduct real-time conversational voice calls with Tavly agents directly through their web browser. Streaming live synthesized audio over WebRTC, this testing method validates round-trip latency, turn-taking dynamics, voice acoustics, and conversational barge-in responsiveness immediately without publishing changes or provisioning phone numbers.

Evaluating agent behavior in the browser provides immediate acoustic and timing feedback before committing to public telephony numbers or live customer rollouts:

| Feature / Dimension | Web Call Testing | Phone Call Testing | LLM Simulation Testing |
| :--- | :--- | :--- | :--- |
| **Channel Type** | Browser WebRTC audio stream | Public PSTN / carrier phone line | Text-based prompt generation |
| **Primary Focus** | Voice acoustics, latency, barge-in | DTMF, carrier codecs, PSTN transfers | Logic regression & pass/fail rubrics |
| **Phone Number Needed** | None (direct browser audio) | Required (outbound/inbound line) | None (console execution) |
| **PSTN Transfer Support** | Fails (agent-to-agent works) | Full PSTN transfer support | Mocked / assertion only |
| **Billing & Concurrency** | Billed per minute; uses concurrency | Billed per minute + telco fees; uses concurrency | Billed per LLM token/run; no concurrency |

## How do you initiate a web call test?

To initiate a **web call test**, navigate to the agent editor in your Tavly console, open the **Test** drawer, and select the **Test Audio** tab. Optionally inject dynamic test variables or custom function mocks, pick an entry node for Conversation Flow agents, then click **Run Test** and grant microphone access.

## What are the primary validation objectives?

The **primary validation objectives** of browser web calls focus on acoustic quality and conversational cadence that text simulations cannot replicate. Developers evaluate real-time response latency, turn-taking pauses, barge-in speech interruption handling, and acoustic synthesis factors like prosody, intonation, pronunciation accuracy, and filler sound naturalness before deploying agents to production.

Browser-based calls evaluate critical acoustic and timing characteristics:

* **Latency and conversational turn-taking**: Measure response turnarounds and verify whether the agent pauses appropriately until you conclude speaking.
* **Barge-in and interruption handling**: Confirm that the agent immediately yields playback and resumes listening when spoken over mid-sentence.
* **Acoustic voice quality**: Assess synthesis naturalness, prosody, intonation, pronunciation accuracy, and filler sound cadence.

For example, after revising an opening greeting, initiate a web call to evaluate turn timing and interrupt the agent mid-sentence to ensure it yields cleanly before deploying the flow to customers.

## What platform limitations apply to browser web calls?

**Platform limitations** in browser web calls stem from the absence of carrier telephony infrastructure and public telephone numbers. External PSTN phone transfers fail (though agent-to-agent transfers work), outbound SMS dispatches fail, and carrier-specific features such as voicemail answering machine detection (**AMD**) and DTMF IVR navigation cannot execute within browser WebRTC sessions.

Be mindful of the following technical boundaries when testing over browser audio:

* **Telephony number transfers fail**: All external PSTN transfers (cold, warm, or agentic warm) fail over browser audio. The console warns you if an agent contains transfer actions, and attempting one returns a transfer error. However, [transfer to another agent](/build/setup/single-multi-prompt/agent-transfer-tool) functions normally, and the test console updates context to the destination agent automatically.
* **SMS dispatch fails**: Outbound SMS actions fail because browser calls lack an associated caller phone number.
* **Voicemail (AMD) and IVR navigation are inactive**: Automated machine detection and DTMF phone-tree processing do not execute in browser environments.

To evaluate carrier audio, DTMF signaling, or live telephony transfers, use [phone call testing](/test/test-phone). To evaluate multi-scenario regression coverage with automated pass/fail grading, use [simulation testing](/test/llm-simulation-testing) and [batch testing](/test/batch-test-simulation).

Web call tests consume standard runtime allocations: they are billed at per-minute voice rates, reserve an active [concurrent call](/deploy/concurrency) channel, and require an account in good financial standing.
