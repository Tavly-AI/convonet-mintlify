The **Tavly LLM Playground** provides a dedicated in-console text environment for testing conversational agents without initiating WebRTC streams or dialing telephone numbers. Located under the **Test LLM** tab of the agent testing drawer, it features two core operational modes: **Manual Chat** for hands-on, turn-by-turn prompt evaluation, and **AI Simulated Chat** for autonomous multi-turn dialog driven by a synthetic persona.

For instance, after configuring a new booking flow, you can simulate a rescheduling request directly in the playground to confirm the agent triggers `check_availability` with intended date arguments before testing with live voice.

## What is the LLM Playground?

The **Tavly LLM Playground** is a dedicated in-console text testing environment designed to validate conversational agent behaviors without initiating WebRTC audio streams or dialing telephone numbers. It features **Manual Chat** for hands-on, turn-by-turn prompt evaluation and **AI Simulated Chat** for autonomous multi-turn dialog driven by a synthetic persona.

Testing agent logic in text first accelerates development cycles by eliminating telephony overhead, audio latency, and phone carrier charges. Developers can isolate reasoning flaws, verify prompt instructions, and review API payload responses before committing to speech synthesis and telephony testing.

| Operational Feature | Manual Chat Mode | AI Simulated Chat Mode |
| :--- | :--- | :--- |
| **Primary Interaction** | Human-driven turn-by-turn input | Autonomous synthetic caller persona |
| **Optimal Use Case** | Prompt iteration & granular state inspection | Multi-turn dialog & behavioral stress-testing |
| **Branch Traversal** | Reassign starting node or state mid-conversation | Autonomous conversational trajectory based on prompt |
| **State & Tool Visibility** | Inline node pathing, tool calls, and API responses | Inline tool dispatches and state transitions |
| **Scenario Persistence** | Save to named thread sessions | Save to Test Cases catalogue for automated suites |
| **Pre-run Setup** | Instant launch from selected node | User prompt (Identity, Goal, Personality) + LLM choice |

## How do you access the LLM Playground?

To access the **LLM Playground**, navigate to your agent configuration screen in the Tavly console, expand the **Test** panel, and select the **Test LLM** tab. You can also import existing conversation transcripts directly into the playground from **Call History**, **Chat History**, **AI QA** records, **Batch Testing History**, or isolated **Conversation Flow** subflows.

The companion **Test Audio** tab is reserved for [live voice testing](/test/test-web). The **Test LLM** tab is intentionally unavailable for [custom LLM](/integrate-llm/overview) architectures and native speech-to-speech voice models because external generation logic and raw audio waveform processing bypass Tavly's internal text simulation engine.

Beyond the agent workspace, you can launch existing conversation transcripts directly into the playground by clicking **View In Test Playground** across several dashboards:

* The detail drawer of any past interaction in [Call History](/features/session-history) or Chat History.
* An individual call record under [AI QA](/ai-qa/overview).
* A specific test execution record inside [Batch Testing History](/test/batch-test-simulation).
* The **Test Subflow** tab within an isolated [Conversation Flow](/build/conversation-flow/overview) node.

## How does Manual Chat mode work?

**Manual Chat mode** enables developers to steer conversational dialog turn by turn by typing manual inputs and observing real-time agent generations. Rather than evaluating pass/fail assertions, this mode focuses on transparent flow inspection: every turn displays active state node transitions, triggered tool invocations, and function payload responses alongside the conversation transcript.

When configuring multi-prompt or Conversation Flow setups, use the **Current State** or **Current Node** selector located above the transcript to designate the starting point of the session. You can also reassign this selector mid-conversation to jump directly between branches without having to navigate preceding conversational turns.

Manage chat sessions using the top-level controls:

* Click **New** to return to mode selection and begin an empty conversation.
* Select **Save** to store the transcript into a named thread, which you can rename using the inline pencil icon.
* Once saved, a trash can icon appears to allow thread deletion.
* Use the thread selector dropdown to toggle between saved sessions and contrast agent responses across distinct runs.

## How do you configure AI Simulated Chat?

**AI Simulated Chat** automates multi-turn testing by deploying a synthetic user model to execute caller turns autonomously against your agent. Configuring this mode requires defining a **user prompt** detailing user objectives, identity, and conversational temperament, alongside an **LLM setting** specifying the model driving the synthetic caller while integrating dynamic variables and function mocks.

The simulation automatically integrates mock responses and test variable values established in the Dynamic Variables menu. Launch the run to watch both entities interact dynamically, with live tool dispatches and state shifts displayed inline.

Structure your synthetic user prompt with clear identity details, primary objectives, and emotional constraints:

```markdown wrap theme={"dark"}
## Identity

Your name is Mike.
Your date of birth is June 10, 1999.
Your order number is 7891273.

## Goal

Your primary objective is to return the package you received and get a refund.

## Personality

You are a patient customer. However, if the conversation becomes too long or complicated, you will show signs of impatience. If the issue remains unresolved, you may become frustrated and angry.
```

During execution, you can pause active exchanges, abort the run, or adjust prompt parameters before re-running:

* **Session control**: Pause or abort active simulations at any turn to modify caller inputs or prompt directives.
* **Persisting test cases**: Click **Save** to persist a scenario. An inline modal allows you to define success evaluation rubrics, dynamic test inputs, and custom function mocks without leaving the editor.
* **Test catalogue export**: Stored scenarios are added to your Test Cases catalogue under the [Simulation tab](/test/llm-simulation-testing), enabling standalone execution or inclusion in [batch](/test/batch-test-simulation) suites.

## How do you debug transcripts interactively?

**Interactive transcript debugging** lets you load completed sessions into an editable Manual Chat canvas from call records, QA logs, or batch runs. Once imported, you can edit historical caller messages, regenerate alternative agent replies, prune isolated turns, replay conversations against updated system prompts, or continue dialog down previously unexplored branches.

Load completed sessions into the Playground from [Batch Testing History](/test/batch-test-simulation), [Call History](/features/session-history), Chat History, or [AI QA](/ai-qa/overview) by selecting **View In Test Playground**. The transcript populates within an editable **Manual Chat** canvas in a new window, offering granular control over past turns:

* **Edit user utterances**: Updating a previous caller message truncates all subsequent exchanges and generates new agent replies from that point forward.
* **Regenerate agent turns**: Discard the current agent response and downstream history to produce an alternative generation.
* **Delete isolated turns**: Prune individual conversational entries without invalidating the broader transcript.
* **Replay conversation**: Click the reload icon beneath the transcript to reset agent replies and re-evaluate every user turn sequentially against the active system configuration.
* **Extend dialog**: Type new manual turns to steer the conversation into unexplored branches.

<Note>
  Transcripts imported from historical records represent finalized calls, leaving the **Send** trigger locked initially. Editing a turn, removing an entry, or re-running an agent reply immediately activates the input box.
</Note>

Because every turn exposes node pathing and tool metadata, interactive replay serves as an essential tool for diagnosing unexpected state shifts or debugging edge cases that are difficult to reproduce from scratch.

## How do you configure dynamic variables and function mocks?

To configure dynamic variables and function mocks, open the **Test Inputs** panel adjacent to the mode selector and commit your test values. Supplying sample values ensures templated variable tags resolve accurately, while function mocks intercept external API tools—such as calendar lookups or SMS triggers—delivering predetermined payloads safely without side effects on production systems.

Access the **Test Inputs** panel adjacent to the mode selector to configure run parameters, clicking **Save** to commit values. The panel contains two operational tabs:

* **Dynamic variables**: Supply sample values for [dynamic variable](/build/context/dynamic-variables) tags to ensure template strings resolve accurately during simulation.
* **Custom function mocks**: Define simulated return structures for agent tools. Whenever an agent attempts an external action—such as checking schedule availability, transferring lines, or sending SMS confirmations—the mock engine intercepts the call and delivers your preconfigured payload, preventing downstream side effects on external production systems.

Configured inputs apply simultaneously across Test LLM and Test Audio environments for the selected agent. Values are stored strictly in local browser storage; they do not synchronize across team workspace accounts or alternate workstations.

For comprehensive configuration guidelines, consult [test variables and mocks](/test/llm-simulation-testing#test-variables-and-mocks).

## How do you perform turn-level response debugging?

To perform turn-level response debugging, click the **Debug** button on any individual conversational turn in the transcript. The built-in diagnostic tool generates **10 successive model iterations**, summarizing generation variance into a statistical frequency distribution to reveal probabilistic output clustering, token stability, and compliance with prompt guidelines under identical input conditions.

When an agent generation deviates from intended guidelines, click **Debug** directly on that conversational turn. The debugger generates 10 successive model iterations, summarizing response variance into a frequency distribution to highlight probabilistic output clustering. To explore comprehensive remediation workflows—including few-shot prompt adjustments, node decomposition, and temperature tuning—see [Debug your agent response](/test/llm-playground-debug).

## What are best practices for testing in the LLM Playground?

**Best practices for LLM Playground testing** center on iterative validation: start with foundational linear flows before introducing edge cases, mock external API dependencies to safeguard production data, inspect tool arguments within turn metadata, and preserve critical edge cases as saved threads or structured simulation test cases for automated regression tracking.

* **Progressive complexity testing**: Start testing with straightforward conversational flows before introducing complex conversational constraints and adversarial inputs.
* **Safe tool mocking**: Mock side-effecting operations like telephone transfers, notifications, and database writes so test executions remain harmless.
* **Turn metadata audits**: Audit tool invocation parameters directly within the turn metadata rather than relying solely on the final conversational wording.
* **Regression suite preservation**: Retain critical debugging sessions as saved threads, converting valuable edge-case dialogues into [simulation test cases](/test/llm-simulation-testing) for automated regression prevention.
