## What are Tavly AI integrations and what capabilities do they unlock?

**Tavly AI integrations** connect your voice and chat agents to external enterprise systems—including **CRMs**, **scheduling calendars**, **customer support helpdesks**, and **knowledge bases**. Authenticating a provider once equips all workspace agents to execute real-time function tools, synchronize customer contacts, write back post-call analytics, and auto-sync knowledge bases.

Connecting your enterprise systems transforms conversational agents from isolated responders into autonomous operators capable of taking real-time actions during live customer calls.

### Core Integration Capabilities

* **Conversational Integration Tools**: Every provider (excluding dedicated knowledge base sources) provides turnkey function tools that agents invoke before, during, or after conversations. Capabilities include caller contact lookups, real-time availability checks, direct calendar bookings, and support ticket creation (see [using tools in an agent](#use-integration-tools-in-an-agent) and [agent workflows](/build/agent-workflow)).
* **Bi-Directional Contact Synchronization & Activity Logging**: Import CRM records into Tavly, write [Post-Call Extraction](/monitor/post-call-analysis-overview) results directly into customer fields, and automatically log transcripts, summaries, and recordings to CRM timelines (detailed in [CRM integrations](/integrations/crm/crm-integrations)).
* **Automated Knowledge Base Synchronization**: Continuously sync documents, spreadsheets, and workspace pages from [Google Drive](/integrations/knowledge-base/google-drive/knowledge-base-sync), [Microsoft OneDrive](/integrations/knowledge-base/onedrive/knowledge-base-sync), and [Notion](/integrations/knowledge-base/notion/knowledge-base-sync) directly into your agent's [knowledge base](/build/context/knowledge-base).

## How do you connect and authenticate a provider?

To connect a provider, navigate to **Integrations → Available** in the Tavly dashboard, select your platform, and supply the required API key, tenant URL, or OAuth credentials. Tavly validates the connection immediately and encrypts all stored tokens; verified connections appear under the **Connected** tab.

Follow these configuration steps:

<Steps>
  <Step title="Open the Integrations page">
    In the Tavly Dashboard, open **Integrations** and select the **Available** tab. Connecting integrations requires an **Admin** or **Developer** workspace role; custom enterprise roles require the `App.Write` and `CRM.Write` permissions.
  </Step>

  <Step title="Authenticate and configure tenant parameters">
    Select your target provider card and supply the requested credentials: an API key or an interactive OAuth sign-in. Providers like Salesforce, Dynamics 365, and Zendesk also require your tenant instance URL; GoHighLevel requires your sub-account Location ID. All credentials are encrypted at rest using AES-256 and are never exposed via client APIs.
  </Step>

  <Step title="Verify connection health">
    Tavly executes an automated authentication handshake test upon connection. Once verified, the connection appears on the **Connected** tab. A healthy connection displays a standard card; failed authentications display a red **Connection error** tag; and the active CRM driving contact sync displays a blue **Contacts sync on** tag.

## How do you configure and use integration tools in an agent?

To use an integration tool, open your agent configuration and add a function under **Functions** (prompt agents) or inside a **Function Node** (conversation flows). Choose the target connection, define input extraction rules, test live outputs, and map returned fields into **dynamic variables** or **agent context**.

Integration tools are available across both agent architecture surfaces:
* **Single & Multi-Prompt Agents**: Add tools under the agent's **Functions** card (see [integration tools for prompt agents](/build/setup/single-multi-prompt/integration-tools)).
* **Conversation Flow Agents**: Add tools directly into a **Function Node** on the canvas (see [integration tools in conversation flow](/build/setup/conversation-flow/function-node/integration-tools-in-conversation-flow)).

### Configuring Tool Inputs

Every tool contains an editable **Name**, an LLM **Description** instructing the agent when to execute it, and an **Input** configuration tab:

* **Value**: A static literal value (e.g., a specific Cal.com Event Type ID). Values can embed `{{variable}}` syntax resolved dynamically at runtime.
* **Description**: Natural language guidance used by the LLM to extract parameters from conversation history (e.g., *"The caller's requested appointment date and time"*).
* **Typed Controls (Select, Boolean, Array)**: Strict enumerated values, boolean toggles, or array rows required by the underlying API schema.

## How do you run integration tools before or after calls?

On the agent's **Workflow** page, attach integration tools as **pre-call functions** (running before audio begins to pre-fetch caller context) or **post-call functions** (running after disconnection to update CRMs or create support tickets). Functions can be sequenced in parallel or chained conditionally with dynamic variables.

### Pre-Call vs. Post-Call Workflows

* **Pre-Call Functions**: Triggered prior to the opening greeting. For example, search a CRM by caller ID to extract the caller's name and tier, allowing the agent to personalize the greeting immediately.
* **Post-Call Functions**: Triggered immediately after call termination. For example, automatically create a Zendesk ticket, schedule a follow-up task, or send an SMS confirmation.
* **Dependency & Execution Graph**: Functions configured in parallel execute concurrently; sequential functions wait for upstream outputs and can ingest upstream dynamic variables.

Learn more about timeout budgets, error fallbacks, and conditional gating in the complete [Agent workflow](/build/agent-workflow) guide.

## Frequently Asked Questions

<AccordionGroup>
  <Accordion title="Can I connect more than one account for the same provider?">
    Yes. Each connection is managed independently, and individual agent tools are bound to a specific connection. The one exception is CRM contact synchronization: only one CRM connection can drive [contact sync](/integrations/crm/crm-integrations) for your workspace at any given time.
  </Accordion>

  <Accordion title="Do I need contact sync to use CRM integration tools?">
    No. Integration tools function immediately once a provider is authenticated. Contact sync and automatic call timeline logging are optional features you enable per connection; [analysis data mappings](/integrations/crm/crm-data-mappings) are configured at the workspace level.
  </Accordion>

  <Accordion title="What happens if a tool call fails mid-conversation?">
    Each integration tool call has an enforced timeout between 3 and 14 seconds depending on the provider. If the external API fails to respond or returns an HTTP error, the tool call fails safely and the agent continues the conversation. Provide prompt instructions directing the agent on how to handle booking or lookup errors gracefully.
  </Accordion>

  <Accordion title="How do I know a connection is healthy?">
    Tavly flags an integration with a red **Connection error** tag on the **Connected** tab if the provider invalidates credentials or fails authorization handshakes. If individual tools fail while the connection appears healthy, inspect provider-side OAuth scopes and permissions, as some APIs return permission errors rather than outright credential rejections.
  </Accordion>
</AccordionGroup>
