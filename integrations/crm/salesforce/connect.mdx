## What is the Tavly AI Salesforce integration and when should you use it?

The **Tavly AI Salesforce integration** connects your Salesforce org to Tavly using an **External Client App** powered by the **OAuth 2.0 client credentials flow**. Connect Salesforce when it acts as your primary system of record to greet synced contacts by name, write back conversation analysis, log calls as Tasks, and execute live SOQL queries.

Connecting your enterprise Salesforce environment establishes direct, programmatic synchronization between conversational voice agents and your core CRM objects:

* **Caller Identification & Personalization**: Automatically match incoming callers against Salesforce Contact records, exposing profile data to agents as dynamic variables.
* **Closed-Loop Property Enrichment**: Automatically write back conversation qualifications, sentiment scores, and extracted customer preferences directly to Contact fields.
* **Automated Activity Logging**: Record each voice call and chat session as a completed **Task** on the Contact's activity timeline, preserving durations and AI summaries.
* **Direct Object Manipulation**: Deploy native [Salesforce agent functions](/integrations/crm/salesforce/agent-functions) to look up opportunities, query custom objects, generate leads, and execute SOQL queries in real time during conversations.

<Note>
  Tavly authenticates with Salesforce exclusively using the **OAuth 2.0 client credentials flow**, eliminating the need for periodic interactive user re-logins.
</Note>

## What prerequisites and editions are required to connect Salesforce?

Connecting Salesforce requires an edition with native API access—**Enterprise**, **Unlimited**, **Developer**, or **Performance** (Professional requires the paid API add-on; Essentials is unsupported). Administrators must possess **System Administrator** permissions to create External Client Apps and configure a dedicated integration user as the **Run As** execution principal.

Before configuring the integration, ensure your environment meets these enterprise criteria:

* **Supported Salesforce Edition**: Enterprise, Unlimited, Developer, or Performance edition. Professional requires Salesforce's paid API feature license; Essentials does not support API integrations.
* **Administrative Privileges**: System Administrator profile permissions, or an administrative permission set permitting External Client App authoring.
* **Dedicated Integration User**: Provision a dedicated service user account (e.g., `tavly-integration@yourdomain.com`) as the **Run As** user to ensure API continuity when employee roles change.

## How do you create an External Client App with client credentials in Salesforce?

To create the app, navigate to **Setup → Apps → External Client Apps → External Client App Manager** in Salesforce and click **New External Client App**. Enable **OAuth Settings**, supply a placeholder callback URL, select the mandatory `api` scope (**Manage user data via APIs**), and check **Enable Client Credentials Flow**.

Follow these setup steps within Salesforce Setup:

<Steps>
  <Step title="Open the External Client App Manager">

In the left navigation sidebar under **Platform Tools**, expand **Apps → External Client Apps** and select **External Client App Manager**. Click the **New External Client App** button in the upper-right corner.

  <Step title="Configure basic app metadata">
    Under **Basic Information**, configure:
    * **External Client App Name**: A clear workspace identifier, such as `Tavly AI`.
    * **API Name**: Automatically generated from the app name; accept default.
    * **Contact Email**: The administrator contact email.
    * **Distribution State**: Leave set to `Local` (the app executes strictly within your org).

  <Step title="Enable OAuth settings and configure scopes">
    Expand **API (Enable OAuth Settings)** and enable OAuth. Enter the following placeholder in the mandatory **Callback URL** field (client credentials flow does not perform browser redirects):

    ```text
    https://api.retellai.com/oauth-callback/salesforce
    ```

    Under **Selected OAuth Scopes**, select:
    * **Manage user data via APIs (api)**: Mandatory. Grants access to execute REST, Bulk, and SOQL API requests.
    * **Perform requests at any time (refresh_token, offline_access)**: Optional. While client credentials do not use refresh tokens, this scope is safe to include.

    <Warning>
      **Do Not Select "Full access (full)" Alone**: The client credentials flow filters out `full` from granted tokens. Since the Salesforce Winter '26 release, token requests lacking other valid scopes fail with `invalid_grant: no valid scopes defined`. Always select `api`.
    </Warning>
  </Step>

## How do you configure OAuth policies and assign the Run As integration user?

Under the app's **Policies** tab, click **Edit**, navigate to **OAuth Flows and External Client App Enhancements**, and check **Enable Client Credentials Flow**. Enter your dedicated integration user's exact **Username** (not email) into the **Run As (Username)** field, and ensure their profile possesses **API Enabled** and object-level permissions.

Because client credentials flows operate without an interactive login, Salesforce evaluates permissions against this designated execution user:

<Steps>
  <Step title="Retrieve Consumer Key and Consumer Secret">
    Open your External Client App in the manager and select the **Settings** tab. Under **App Settings**, click **Consumer Key and Secret** (Salesforce may require email verification). Securely copy:
    * **Consumer Key**: Tavly **Client ID**.
    * **Consumer Secret**: Tavly **Client Secret**.

  <Step title="Validate Run As user profile permissions">
    Confirm that the integration user's profile or assigned permission sets grant necessary access:
    * **API Enabled**: Required system permission on user profile.

    * **Task Object**: Create permission to support automated timeline activity logging.
    * **Agent Function Objects**: Read/Edit permissions on Lead, Account, Opportunity, Case, or custom objects utilized in [Salesforce agent functions](/integrations/crm/salesforce/agent-functions). Creating Notes requires Edit access on the parent record.
  </Step>

  <Step title="Save policies">
    Click **Save** to finalize OAuth policies.

## How do you connect and authenticate Salesforce inside Tavly?

In the Tavly dashboard, open **Integrations → Available**, select **Salesforce**, and input your connection alias, **Instance URL** (`https://<domain>.my.salesforce.com`), **Client ID** (Consumer Key), and **Client Secret** (Consumer Secret). Click **Connect** to trigger an automated API handshake verification test before configuring contact synchronization.

Follow these connection steps:

<Steps>
  <Step title="Initiate Salesforce connection">
    In the Tavly Dashboard, navigate to **Integrations → Available**, locate **Salesforce**, and click **Connect** (or **Add Account**).
  </Step>

  <Step title="Supply connection parameters">
    Enter the required authentication parameters:

    | Field Name | Parameter Requirements |
    | :--- | :--- |
    | **Connection name** | Workspace alias; prefilled with `Salesforce - OAuth`. |
    | **Instance URL** | Your lowercase My Domain URL in the form `https://<domain>.my.salesforce.com`. |
    | **Client ID** | The Salesforce **Consumer Key**. |
    | **Client Secret** | The Salesforce **Consumer Secret**. |

    <Warning>
      **My Domain URL Validation**: The instance URL must match the format `https://<domain>.my.salesforce.com` without paths. Lightning portal URLs (`.lightning.force.com`) and naked `.salesforce.com` domains are rejected. Sandboxes in the format `https://acme--dev.sandbox.my.salesforce.com` are supported.
    </Warning>

    <Frame caption="The Salesforce connection modal in the Tavly dashboard.">

## How do you troubleshoot common Salesforce connection and policy errors?

If connection fails initially, allow up to **30 minutes** for Salesforce app replication, verify the My Domain URL format (excluding `.lightning.force.com`), and confirm **Enable Client Credentials Flow** is checked in both creation and policy screens. For IP restrictions, set **IP Relaxation** to **Relax IP restrictions** on the app's Policies tab.

### Diagnostic Matrix

<AccordionGroup>
  <Accordion title="Connecting fails immediately after app creation">
    Salesforce requires up to 30 minutes to replicate newly registered External Client Apps across its global token infrastructure. If validation fails, wait 10 to 15 minutes and retry before modifying credentials. Verify that **Enable Client Credentials Flow** is active on both creation settings and the Policies tab.
  </Accordion>

  <Accordion title="Tavly rejects the supplied Instance URL">
    Retrieve your canonical My Domain URL from Salesforce Setup under **Company Settings → My Domain**. Ensure the URL starts with `https://` and ends in `.my.salesforce.com`. Remove paths, query strings, and trailing slashes.
  </Accordion>

  <Accordion title="Active connection shows an authentication error (HTTP 401 / INVALID_SESSION_ID)">
    This error indicates that Salesforce rejected the access token request. Common causes include rotated Consumer Secrets, disabled Run As user accounts, or modified OAuth policies. Reconnect with refreshed credentials.
  </Accordion>

  <Accordion title="API requests are blocked by corporate IP restrictions">
    If your Salesforce organization enforces login IP ranges on profiles or OAuth apps, cloud-based API calls from Tavly are rejected. On the External Client App's **Policies** tab, set **IP Relaxation** to **Relax IP restrictions**, or exempt the Run As integration user profile from login range filters.
  </Accordion>

  <Accordion title="Rotating the Consumer Secret">
    Navigate to **Integrations → Connected** in Tavly and open Salesforce settings. Enter the newly generated Consumer Secret (and Consumer Key if altered) and select **Reconnect**. Tavly validates the new credentials immediately without disrupting existing contact sync mappings.
  </Accordion>
</AccordionGroup>

## Frequently Asked Questions

<AccordionGroup>
  <Accordion title="Can I connect more than one Salesforce organization to a Tavly workspace?">
    You can create multiple distinct Salesforce connections. However, only one CRM connection across all providers can drive automated two-way contact synchronization for your workspace at any given time.
  </Accordion>

  <Accordion title="Why does Salesforce reject 'Full access (full)' scope for client credentials?">
    Since Salesforce Winter '26, client credentials flow tokens automatically filter out the `full` scope. A request configured solely with `full` is rejected with `invalid_grant: no valid scopes defined`. Always select `Manage user data via APIs (api)` instead.
  </Accordion>

  <Accordion title="What profile permissions does the Salesforce Run As user require?">
    The Run As user requires **API Enabled** on their profile, Read/Edit on Contact, Create on Task (for activity logging), and appropriate Read/Edit permissions on Lead, Account, Opportunity, Case, or custom objects touched by agent function tools.
  </Accordion>
</AccordionGroup>
