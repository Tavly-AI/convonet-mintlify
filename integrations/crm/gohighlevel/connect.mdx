## What is the Tavly AI GoHighLevel integration and when should you use it?

**Tavly AI GoHighLevel integration** connects your GoHighLevel sub-account to Tavly using a Private Integration token and Location ID. Connect GoHighLevel when it acts as your primary system of record to greet synced contacts by name, fire workflows via contact tags, advance pipeline opportunities, and book appointments directly on native calendars.

Connecting GoHighLevel requires a **Private Integration token** and the sub-account's **Location ID**. A single connection unifies both [contact sync](/integrations/crm/gohighlevel/contact-sync) and [agent functions](/integrations/crm/gohighlevel/agent-functions): conversational agents work the sub-account's contacts, tags, and opportunities, and Tavly keeps the records current.

<Note>
  A GoHighLevel connection is scoped to **one sub-account (location)**. An agency managing several locations connects each one separately.
</Note>

### Core use cases for integrating GoHighLevel

Connect GoHighLevel when you want your voice and conversational agents working directly from your CRM without manual data transfers:

* **Call or text people who already exist in GoHighLevel**: Contacts sync into Tavly automatically, allowing your agent to greet callers by name and identify their pipeline stage immediately.
* **Fire GoHighLevel workflows from conversation outcomes**: The **Add Contact Tags** tool tags the contact in real time. Because GoHighLevel workflows trigger on tags, outcomes like `booked` or `interested` initiate existing follow-up automation.
* **Work deals directly over phone calls**: Agents can list a contact's opportunities, advance deals across pipeline stages, or create new opportunities when callers qualify.
* **Book appointments on sub-account calendars**: The connection reads real-time slot availability to book, reschedule, or cancel appointments, unifying record management and scheduling in one integration.

Agents also manage contacts, tasks, notes, and appointments through [integration tools](/integrations/crm/gohighlevel/agent-functions#which-gohighlevel-function-tools-are-available-for-conversational-agents) and book sub-account [calendars](/integrations/crm/gohighlevel/agent-functions#how-do-agents-book-and-manage-sub-account-calendars).

```
[Inbound / Outbound Call]
         │
         ▼
 ┌───────────────┐        Fetch Contact & Pipeline Data
 │   Tavly AI    │ ◄────────────────────────────────────────► ┌─────────────────────────┐
 │ Voice Agents  │                                            │  GoHighLevel Sub-Account │
 └───────┬───────┘                                            │  (Location-Scoped API)   │
         │                                                    └────────────┬────────────┘
         │ 1. Tag Contact (`booked`, `qualified`)                          │
         │ 2. Create / Update Opportunities                                │ Triggers native
         │ 3. Schedule Calendar Appointments                               │ automations
         ▼                                                                 ▼
 ┌─────────────────────────────────────────────────────────────────────────────┐
 │ Native GoHighLevel Workflows (SMS Confirmations, Pipeline Automations)      │

```

> **Real-World Scenario:** An agency manages an inbound appointment line for a med spa location using Tavly. The agent identifies the caller, personalizes the dialogue using their CRM profile, books an appointment slot, and tags the record as `booked`. The location's native GoHighLevel workflow immediately dispatches an SMS confirmation without altering existing workflows.

## What prerequisites are required to connect a GoHighLevel sub-account?

Connecting GoHighLevel requires administrative access to the specific **sub-account (location)** you wish to integrate. Because Private Integrations are scoped at the location level, tokens must be created within the sub-account rather than at the agency level. If disabled, enable Private Integrations under sub-account Labs settings first.

* **Admin Permissions**: Administrative privileges within the designated GoHighLevel sub-account.
* **Location Scope**: Private Integrations exist at both the agency and sub-account levels; Tavly requires a **location-scoped** token generated inside the specific sub-account.
* **Labs Activation (if required)**: If **Private Integrations** is not visible under **Settings**, toggle it on under **Settings → Labs** in the agency or sub-account view.

## How do you create a Private Integration token and configure scopes in GoHighLevel?

In the sub-account, navigate to **Settings → Private Integrations**, click **Create new Integration**, and name it `Tavly AI`. On the **Scopes** tab, select required permissions covering contacts, opportunities, custom fields, and calendars. Save the integration and immediately copy the generated access token, as it is displayed only once.

    <Note>
      If **Private Integrations** isn't in the Settings menu, enable the feature under **Settings > Labs** (agency or sub-account view) first. By default admins can create Private Integrations; access can be restricted per user under **Roles & Permissions** (**Settings > Team** at the agency, **Settings > My Staff** in a sub-account).

## What scopes are required for GoHighLevel contact sync, tools, and booking?

Contact synchronization and tools require `contacts.readonly` and `contacts.write`. Opportunity workflows require `opportunities.readonly/write`. Reading custom field definitions requires `locations/customFields.readonly`. Calendar checking, booking, and rescheduling require `calendars.readonly`, `calendars/events.readonly`, and `calendars/events.write`. Missing scopes trigger authorization errors that flag the connection as broken.

| Scope Slug | Operational Purpose | Feature Dependency |
| :--- | :--- | :--- |
| `contacts.readonly`<br />`contacts.write` | Enables initial contact sync, connection credential tests, contact lookups, profile updates, contact tagging, task creation, notes, and fetching a contact's appointment history. | Contact Sync, Connection Test, Agent Contact Tools |
| `opportunities.readonly`<br />`opportunities.write` | Grants permissions to read pipelines, list existing opportunities, create new deals, and advance deal stages during live calls. | Pipeline Management, Opportunity Tools |
| `locations/customFields.readonly` | Fetches custom field definitions from GoHighLevel to populate mapping dropdowns in Tavly. | Contact Field Mapping |
| `calendars.readonly`<br />`calendars/events.readonly`<br />`calendars/events.write` | Grants access to check appointment slot availability, book confirmed slots, reschedule bookings, and process cancellations on sub-account calendars. | [Calendar Tools](/integrations/crm/gohighlevel/agent-functions#how-do-agents-book-and-manage-sub-account-calendars) |

<Warning>
  Grant all required scopes during initial setup. Without `contacts.readonly`, Tavly's automated connection test fails immediately. Furthermore, if a live agent function encounters an omitted scope, GoHighLevel returns an identical authorization error code to an expired token, flagging the integration with a **Connection error** status.
</Warning>

## How do you find your GoHighLevel sub-account Location ID?

To locate your Location ID, open the sub-account and navigate to **Settings → Business Profile**; the ID is displayed at the top of the General Information card. Alternatively, inspect your browser address bar while inside the sub-account and copy the alphanumeric string immediately following `/location/` in the URL.

### Methods to retrieve your Location ID

1. **Sub-Account Business Profile**: Navigate to **Settings > Business Profile** inside your sub-account. Locate the **Location ID** field in the upper right corner of the **General Information** section and click the copy icon.
2. **Browser URL Extraction**: When viewing the sub-account dashboard, inspect the current browser URL. The Location ID is the unique alphanumeric segment following `/location/` (for example, `ve9EPM428h8vShlRW1KT` in `https://app.gohighlevel.com/location/ve9EPM428h8vShlRW1KT/dashboard`).

## How do you rotate Private Integration tokens and manage scopes?

To rotate credentials safely, select **Rotate and expire this token later** in GoHighLevel, preserving previous token validity for **7 days** while swapping keys. In Tavly, open connection settings and click **Reconnect** with the new token. Additional scopes can also be added in GoHighLevel at any time without token regeneration.

* **Modify Scopes Dynamically**: Add or modify permissions within the Private Integration's **Scopes** tab anytime without regenerating the access token. Added scopes take effect immediately across existing agent calls.
* **Scheduled Token Rotation**: GoHighLevel recommends rotating access tokens every **90 days**. When rotating in **Settings > Private Integrations**:
  * **Rotate and expire this token later**: Retains the existing token for a **7-day grace period**, allowing seamless credential swapping in Tavly without downtime.
  * **Rotate and expire this token now**: Revokes the active token immediately, causing Tavly operations to fail until updated credentials are provided.
* **Reconnect in Tavly**: Go to **Integrations → Connected** in Tavly, click your GoHighLevel connection settings, replace the existing token, and click **Reconnect**. Tavly validates the new credentials immediately, preserving all custom field mappings and synced contact records.

## How do you troubleshoot common GoHighLevel connection errors?

If connecting fails with an authorization error, verify you supplied a sub-account token rather than an agency-level API key. If an active connection errors, check whether Private Integration tokens were rotated or deleted, or if a tool encountered an omitted scope that GoHighLevel reported as an unauthorized token.

<AccordionGroup>
  <Accordion title="Connecting fails with an authorization error">
    Confirm that you pasted a **Private Integration token** generated directly from the same sub-account whose **Location ID** you entered. Agency-level tokens, tokens generated in different sub-accounts, and deprecated legacy v1 API keys cannot authenticate location endpoints.
  </Accordion>

  <Accordion title="The connection errored after working successfully">
    Tavly flags an integration with an error status when GoHighLevel returns an unauthorized HTTP response. This typically occurs when a token has been rotated, expired, or deleted, or when an agent attempts an operation lacking required API scopes. To resolve, edit the connection in Tavly, paste an active token (or enable omitted scopes in GoHighLevel), and select **Reconnect**.
  </Accordion>
</AccordionGroup>
