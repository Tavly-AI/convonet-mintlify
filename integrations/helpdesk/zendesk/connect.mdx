## What is the Tavly AI Zendesk integration and when should you use it?

**Tavly AI Zendesk integration** connects your Zendesk customer support workspace to Tavly using OAuth authentication and your Zendesk tenant URL. Connect Zendesk when you want conversational voice agents operating at the front of your support queue to identify callers, retrieve open tickets, file new support requests, and append conversation summaries.

Connecting Zendesk requires your Zendesk subdomain URL and an OAuth sign-in. A single connection activates live [agent functions](/integrations/helpdesk/zendesk/agent-functions): conversational agents identify callers, manage ticket statuses, and record call outcomes as public customer replies or private internal notes.

### Architecture: Helpdesk OAuth & real-time tool bridge

```
┌─────────────────────────────────┐                 ┌─────────────────────────────────┐
│            Tavly AI             │                 │        Zendesk Helpdesk         │
│                                 │                 │                                 │
│ 1. Initiate OAuth Handshake ────┼── Subdomain ───►│ `https://acme.zendesk.com`      │
│ 2. Authorize Permissions ───────┼── OAuth Grant ─►│ Read/Write Scopes Authenticated │
│ 3. Secure Token Storage ────────┼◄── Refresh Token┤ Continuous API Session Bound    │
│                                 │                 │                                 │
│ 4. Caller Identification ───────┼── Phone Lookup ─►│ Match Caller via `Search User`  │
│ 5. Real-Time Ticket Actions ────┼── Live REST ───►│ Create / Update / Comment       │
└─────────────────────────────────┘                 └─────────────────────────────────┘
```

### When to connect Zendesk

Deploy Tavly with Zendesk when your customer operations run on Zendesk and you want conversational AI handling tier-1 support interactions:

* **Identify callers without requesting ticket numbers**: The agent automatically searches Zendesk using incoming caller ID, matches the customer profile, and retrieves active tickets before the caller finishes explaining their issue.
* **Automate ticket creation from calls**: When callers report new incidents or inquiries, the agent creates a ticket with structured subject lines and detailed descriptions summarized directly from the conversation.
* **Maintain the ticket as the definitive system of record**: Conversation outcomes, transcripts, and resolution notes append to tickets as public replies visible to customers or internal notes reserved for support staff.

> **Real-World Implementation:** A SaaS company's inbound support line utilizes a Tavly conversational agent. The agent resolves caller identities via phone number, reads the status of open engineering tickets, and appends a private note summarizing the call. A human agent only intervenes if the issue requires manual escalation.

## What prerequisites are required to connect Zendesk?

Connecting Zendesk requires an active Zendesk account with an **Agent or Admin role**, your primary **subdomain tenant URL**, and a dedicated integration service user. End-user accounts cannot query tickets or search customer profiles via API. Dedicated service users guarantee that ticket ownership remains persistent regardless of personnel turnover.

* **Zendesk Agent or Admin Role**: Tavly executes API operations under the identity of the account that completes OAuth consent. End-user accounts lack permissions to search other profiles or work the ticket queue.
* **Standard Tenant Subdomain URL**: Your official Zendesk origin URL in the format `https://your-subdomain.zendesk.com`. Host-mapped vanity domains (e.g., `support.yourcompany.com`) or URLs containing path parameters are not supported.
* **Dedicated Integration Service User**: We strongly advise authorizing with a dedicated service account (e.g., `tavly-integration@yourcompany.com`). This ensures tickets and notes are clearly attributed to the integration and prevents automated workflows from breaking if an employee leaves the company.

## How do you authenticate and connect Zendesk in Tavly?

In the Tavly Dashboard, navigate to **Integrations → Available**, locate **Zendesk**, and click **Connect**. Provide a connection name, input your Zendesk tenant URL, and complete the OAuth authorization popup using your integration user credentials. Tavly validates the connection by fetching the user's profile and immediately activates live agent tools.

## What OAuth access scopes does Tavly require in Zendesk?

During OAuth authorization, Tavly requests Zendesk's global `read` and `write` API scopes, which provide permissions to read customer profiles and tickets and write ticket updates, comments, and notes. The actual operations an agent can execute remain strictly constrained by the Zendesk role assigned to the connected user account.

Zendesk bundles API capabilities into broad OAuth scopes:

| Requested Scope | Operational Scope Coverage |
| :--- | :--- |
| `read` | Grants read access to search users, inspect customer profile attributes, and retrieve active tickets. |
| `write` | Grants permission to create support tickets, modify ticket fields, and append public comments or internal notes. |

<Note>
  OAuth scopes define application access limits, but the authorizing account's **Zendesk role** controls execution authority. See [required user roles](/integrations/helpdesk/zendesk/agent-functions#what-zendesk-user-roles-and-permissions-are-required-for-agent-tools) for details on how Full Agent, Light Agent, and End User permissions impact tool behavior.
</Note>

## How do you troubleshoot common Zendesk connection errors?

Troubleshoot connection failures by verifying the tenant URL structure and token validity. If connecting fails during sign-in, confirm you entered a clean subdomain URL without trailing paths or vanity host-mapping. If an existing connection errors, the token was likely revoked or the account suspended in Zendesk Admin Center.

<AccordionGroup>
  <Accordion title="Connecting fails or the OAuth popup displays an error">
    Validate your Zendesk tenant URL format. It must follow the exact origin structure `https://your-subdomain.zendesk.com` with no trailing slashes or subpaths. Custom host-mapped vanity domains (e.g., `https://support.acme.com`) will cause OAuth validation to fail.
  </Accordion>

  <Accordion title="The connection card displays an error badge after operating successfully">
    Tavly flags a connection with an error state when Zendesk rejects the stored OAuth token. This typically occurs if the authorizing account was suspended, deactivated, or if authorization was revoked in Zendesk under **Admin Center > Apps and integrations > APIs > External OAuth clients**. Open the connection settings in Tavly and click **Reconnect** to re-authenticate with an active agent account.
  </Accordion>

  <Accordion title="Tool executions fail while the connection card remains connected">
    A role modification does not invalidate the OAuth connection, but it directly limits tool execution capabilities. For example, downgrading an account from Agent to Light Agent prevents the agent from posting public replies or editing external tickets. Reconnect the integration using an account holding a full **Agent** or **Admin** role.
  </Accordion>
</AccordionGroup>

## Frequently asked questions about connecting Zendesk

Connecting Zendesk to Tavly creates a direct, live API bridge for real-time ticket operations without persistent data synchronization. Custom vanity domains are not supported during OAuth setup and must use standard `zendesk.com` subdomains. Authorizations can be reviewed or revoked anytime in the Zendesk Admin Center.

<AccordionGroup>
  <Accordion title="What Zendesk user role is required to connect Tavly?">
    Connecting requires an account with an **Agent** or **Admin** role. End-user accounts cannot search users or work tickets through the API. While Light Agents can connect, their comments are restricted to internal private notes and cannot create public replies.
  </Accordion>

  <Accordion title="Can I use a custom vanity domain or host-mapped URL?">
    No. Zendesk's OAuth service requires the native Zendesk subdomain URL (e.g., `https://acme.zendesk.com`). Host-mapped domains (e.g., `https://help.acme.com`) will result in an authorization failure during sign-in.
  </Accordion>

  <Accordion title="How do I revoke Tavly AI's access to Zendesk?">
    Administrators can revoke Tavly's OAuth authorization at any time inside Zendesk by navigating to **Admin Center > Apps and integrations > APIs > External OAuth clients**, locating the Tavly AI integration, and revoking client access.
  </Accordion>
</AccordionGroup>
