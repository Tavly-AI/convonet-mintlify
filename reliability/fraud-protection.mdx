## What is fraud protection for voice AI agents?

**Tavly fraud protection** provides telecom-grade security controls to defend voice AI agents against toll fraud, robotic spam, and International Revenue Sharing Fraud (IRSF). By combining **IP-and-destination rate limiting**, **granular geographic call filtering**, and **public key security**, Tavly ensures telephony budgets remain protected from automated exploit scripts.

These capabilities complement foundational [abuse prevention measures](/reliability/prevent-abuse) by giving organizations fine-grained administrative and programmatic control over exactly where, how often, and by whom AI voice agents can be engaged.

### Core Fraud Protection Pillars

| Protection Mechanism | Control Layer | Enforced Scope | Operational Impact |
| :--- | :--- | :--- | :--- |
| **Public Key Rate Limiting** | Frontend / Client API | Caller IP + Destination Phone Number | Blocks high-velocity dial scripts and repeated spam calls to premium destinations. |
| **Geographic Filtering** | Telephony Carrier Gateway | Per-Phone-Number Country Allowlist | Rejects inbound and outbound calls outside designated business regions. |
| **Sanction Compliance** | Global SIP Edge | Mandatory Global Embargo List | Hard-blocks all traffic to/from OFAC-sanctioned jurisdictions regardless of config. |
| **Bot Mitigation Integration** | Web Application Layer | Google reCAPTCHA v3 Scoring | Eliminates headless browser automation and fake form submission attacks. |

## How do you enable rate limiting on public keys?

To enable rate limiting, open **API Keys → Public Keys** in your Tavly dashboard, choose your public key, toggle on **Fraud Protection**, and save. Requests originating from frontend widgets or client SDKs will automatically be throttled by **caller IP address** and **target destination phone number**.

When building public-facing web applications or embedding voice widgets, frontend clients authenticate calls using [public keys](/accounts/keys/public-keys). Activating fraud protection adds automated abuse mitigation directly to the credential.

### Enabling Fraud Protection via Dashboard

1. Navigate to **API Keys → Public Keys** in your Tavly dashboard.
2. Click on the public key you wish to configure (or click **Create New Key**).
3. Toggle on **Fraud Protection**.
4. Click **Save Changes**.

### Rate Limiting Evaluation Logic

When fraud protection is active on a public key:
* **Composite Key Evaluation**: Every call initiation is evaluated against a unique composite fingerprint: `hash(Client IP Address + Target Destination Number)`.
* **IRSF Pumping Prevention**: If a malicious script attempts to generate high-frequency calls from a single IP to expensive international or premium-rate numbers, excess attempts are immediately dropped.
* **Broad Surface Coverage**: Rate limits apply uniformly across outbound phone calls and SMS interactions initiated via public key authentication.

<Tip>
  **Enhanced Bot Defense**: For maximum security on browser-facing widgets, combine public key fraud protection with [Google reCAPTCHA v3 protection](/accounts/keys/public-keys#google-recaptcha-v3-protection-optional) to analyze behavioural telemetry and drop automated bots before calls initiate.
</Tip>

## How do you configure geographic call restrictions for phone numbers?

Configure geographic restrictions by navigating to **Phone Numbers** in your Tavly dashboard, selecting a number, and populating **Allowed Inbound Countries** or **Allowed Outbound Countries** with ISO alpha-2 codes. Calls originating from or dialed to unlisted countries are **automatically blocked and dropped at the telecom edge**.

Geographic restrictions provide critical defense against International Revenue Sharing Fraud (IRSF) by ensuring phone numbers cannot dial or receive calls from unauthorized jurisdictions.

### Configuring Allowed Inbound Countries

Restrict which countries are permitted to place inbound calls to your Tavly phone numbers:

1. Navigate to **Phone Numbers** in the Tavly dashboard.
2. Select the specific phone number you wish to configure.
3. Under **Allowed Inbound Countries**, select the allowed nations from the dropdown.

Changes save automatically.

When an inbound call originates from a country code not included on your allowlist, Tavly terminates the signaling handshake and rejects the call immediately.

### Configuring Allowed Outbound Countries

Restrict which destination countries your Tavly agents are allowed to dial:

1. Navigate to **Phone Numbers** in the Tavly dashboard.
2. Select the target phone number.
3. Under **Allowed Outbound Countries**, add the authorized destination countries.

Changes save automatically.

When an outbound call or call transfer is initiated to a country code not on this allowlist, Tavly blocks the call before SIP INVITE transmission, preventing carrier billing events.

## How do you configure geographic restrictions programmatically via API?

To configure geographic restrictions via API, send a `PATCH` request to the `/update-phone-number/{phone_number}` endpoint with `allowed_inbound_country_list` and `allowed_outbound_country_list` arrays containing **ISO 3166-1 alpha-2 codes**. Pass `null` to remove geographic restrictions and restore global dialing permissions.

Programmatic configuration allows engineering teams to dynamically synchronize dialing permissions with customer tenant profiles, CRM settings, or automated fraud-monitoring scripts.

### Setting Country Restrictions via API

Use the [Update Phone Number API](/api-references/update-phone-number) to enforce regional restrictions:

```bash theme={"dark"}
curl -X PATCH "https://api.tavlyai.com/update-phone-number/+14155551234" \
  -H "Authorization: Bearer YOUR_API_KEY" \
  -H "Content-Type: application/json" \
  -d '{
    "allowed_inbound_country_list": ["US", "CA", "GB"],
    "allowed_outbound_country_list": ["US", "CA"]
  }'
```

* Specify country identifiers using standardized [ISO 3166-1 alpha-2](https://en.wikipedia.org/wiki/ISO_3166-1_alpha-2) two-letter format (e.g., `US` for United States, `CA` for Canada, `GB` for United Kingdom, `AU` for Australia).

### Clearing Country Restrictions via API

To remove country-level restrictions and permit global inbound/outbound routing, set the respective arrays to `null`:

```bash theme={"dark"}
curl -X PATCH "https://api.tavlyai.com/update-phone-number/+14155551234" \
  -H "Authorization: Bearer YOUR_API_KEY" \
  -H "Content-Type: application/json" \
  -d '{
    "allowed_inbound_country_list": null,
    "allowed_outbound_country_list": null
  }'
```

## Which sanctioned countries are permanently blocked?

Tavly enforces mandatory international compliance by **unconditionally blocking** all inbound and outbound telephony traffic to sanctioned nations, regardless of account or number-level settings. Any voice call or SMS attempt directed to or originating from these jurisdictions is **automatically rejected at the SIP signaling layer**.

These global restrictions apply across all telephony providers, custom SIP trunks, and API tiers:

| Sanctioned Jurisdiction | ISO 3166-1 Alpha-2 Code | Inbound Status | Outbound Status |
| :--- | :--- | :--- | :--- |
| **Cuba** | `CU` | Blocked | Blocked |
| **Iran** | `IR` | Blocked | Blocked |
| **North Korea** | `KP` | Blocked | Blocked |
| **Syria** | `SY` | Blocked | Blocked |
| **Russia** | `RU` | Blocked | Blocked |
| **Belarus** | `BY` | Blocked | Blocked |
| **Venezuela** | `VE` | Blocked | Blocked |

<Warning>
  Calls originating from or terminating in these regions receive an immediate `403 Forbidden` or `603 Decline` SIP response status code. These restrictions cannot be overridden or bypassed.
</Warning>

## What are the operational best practices for telephony fraud defense?

Implement a defense-in-depth security model by enabling **fraud protection on all public keys**, combining frontend widgets with **Google reCAPTCHA v3**, and starting with a **strict country allowlist**. Continuously monitor blocked calls through **event webhooks** and perform quarterly audits of your authorized calling jurisdictions.

Follow these proven engineering best practices to minimize attack surfaces:

1. **Activate Fraud Protection on Every Public Key**: Enable the fraud protection toggle across all public keys deployed in production frontends to enforce baseline IP-and-destination velocity throttling.
2. **Combine with Google reCAPTCHA v3**: For web-initiated calling buttons and browser lead forms, enforce reCAPTCHA token verification to eliminate headless browser scripts.
3. **Enforce Least-Privilege Country Allowlists**: Configure outbound country lists to include only regions where active business operations exist. Avoid unconstrained global dialing (`null`).
4. **Subscribe to Webhook Alerts**: Configure [call event webhooks](/monitor/webhook-overview) to monitor rejected call patterns, tracking sudden spikes in geographic blocking or rate-limited sessions.
5. **Conduct Regular Audits**: Review allowed inbound and outbound country configurations quarterly to prune obsolete dialing destinations and adapt to evolving business footprints.
