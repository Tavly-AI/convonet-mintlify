## Why is your Tavly AI agent producing incorrect responses?

Tavly AI agents produce incorrect responses when **lightweight LLMs lack sufficient reasoning depth**, **system prompts become overly complex**, or **few-shot conversational examples are missing**. Systematic debugging isolates whether errors stem from underlying model limitations, ambiguous prompt instructions, unhandled edge cases, or misconfigured tool and function call parameters.

When an agent deviates from its intended persona, fails to invoke tools, or hallucinates inaccurate statements, work methodically through the primary diagnostic areas below:

| Diagnostic Area | Failure Symptom | Recommended Action | Expected Impact |
| :--- | :--- | :--- | :--- |
| **Model Capability** | Agent ignores negative constraints or misinterprets multi-condition prompts | Upgrade from lightweight models (e.g., `4.1-mini`) to flagship models (e.g., `gpt-4.1`) | Significantly improves reasoning depth, instruction adherence, and edge-case handling |
| **Prompt Architecture** | Conflicting answers, skipped questions, or conversational loops | Break monolithic prompts into sequential steps with explicit transition conditions | Enforces linear conversational progress and eliminates instruction competition |
| **Few-Shot Guidance** | Agent phrases answers awkwardly or misidentifies intent in edge cases | Add **Fine-Tuning Examples** to ground expected input-output mappings | Teaches concrete response styles and state transitions by example |
| **Tool & Function Schema** | Agent triggers wrong tools or outputs invalid argument payloads | Clarify function descriptions and constrain argument schemas strictly | Eliminates hallucinated parameters and ensures reliable backend execution |

## How do you upgrade model capability to fix response errors?

If your agent fails to follow complex instructions or hallucinates across lengthy multi-turn conversations, verify your selected model architecture. Lightweight models like **GPT-4.1-mini** prioritize speed over reasoning; switching to high-capability models such as **GPT-4.1** provides the contextual comprehension required to execute intricate, rule-heavy dialogue workflows accurately.

## How do you restructure complex prompts for higher accuracy?

To resolve persistent instruction-following errors, refactor monolithic prompts into **sequential, discrete conversational steps** with **explicit transition conditions**. Incorporate standardized [prompt engineering](https://www.promptingguide.ai/) techniques, prune redundant instructions, and enforce unambiguous behavioral constraints so the language model evaluates only one clear operational objective at a time.

When prompts grow beyond manageable complexity, adhere to these structural best practices:

* **Single Responsibility per Step**: Rather than commanding an agent to *"collect customer name, email, billing address, and issue description,"* partition data collection into sequential questions.
* **Explicit Guardrails**: Frame instructions with explicit boundaries (e.g., *"Never confirm a booking without first receiving a validated confirmation number from the lookup tool"*).
* **Separate Knowledge from Instructions**: Offload lengthy product catalogs, policy documents, and company FAQs into a dedicated [Knowledge Base](/build/context/knowledge-base) rather than overloading the primary prompt buffer.
* **Transition Logic**: For multi-turn workflows, specify exact triggers for step progression (e.g., *"Once the user confirms their account number, transition to Step 2: Verification"*).

## How do fine-tuning examples and tool audits resolve edge cases?

When prompt adjustments alone cannot enforce compliance, inject **fine-tuning examples** to provide few-shot demonstration pairs directly anchoring intended phrasing and behavior. Additionally, review **custom function and tool call definitions**, ensuring parameters, JSON schemas, and error responses provide unambiguous guidance for the language model to parse.

### 1. Add Few-Shot Fine-Tuning Examples
Few-shot examples provide the model with concrete demonstrations of realistic caller inputs paired with exact expected agent responses:
* **Teach Tone and Syntax**: Reinforce natural conversational phrasing without inflating system prompt instructions.
* **Clarify Ambiguous Phrasing**: Supply examples showing how the agent should interpret uncommon regional slang, ambiguous affirmations, or multi-part questions.
* **Guide State Transitions**: In conversation flows, use [Fine-Tune Examples](/build/setup/conversation-flow/advanced/finetune-examples) to demonstrate exact mapping between transcripts and node transitions.

### 2. Review and Audit Function Calls
If incorrect responses involve erroneous or hallucinated tool invocations:
* **Validate Function Descriptions**: Ensure the description in your [Custom Function](/build/setup/single-multi-prompt/custom-function) explicitly clarifies *when* and *why* the tool must be invoked.
* **Restrict Parameter Types**: Define strict JSON schemas with clear property descriptions and required fields.
* **Mock and Test in Playground**: Use the [LLM Playground Debugger](/test/llm-playground-debug) to simulate tool responses and verify parameter payloads before pushing changes to live calls.
