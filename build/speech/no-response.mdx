## What are Silent Responses?

Silent responses handle moments in a call where a user requests a temporary conversational pause (e.g., "hold on," "give me a second"). Instead of talking over the user, the agent remains completely quiet while keeping the line open.

This is strictly a conversational pause; it does not place the caller on a traditional PBX-level hold or trigger hold music.

To facilitate this, Tavly natively registers a built-in stop token inside the language model runtime: `NO_RESPONSE_NEEDED`. 

When the model emits this exact string, text generation halts immediately and the synthesis engine produces absolutely zero audio output.

## How do you implement Silent Responses?

You implement conversational silence by adding a hardcoded directive directly into your primary system prompt, instructing the LLM exactly when to trigger the stop token.

Add the following explicit instruction into your agent's prompt architecture:

```markdown theme={"dark"}
- If the user asks you to wait or says "hold on", reply strictly with: "NO_RESPONSE_NEEDED"
```

<Note> **Reasoning Model Exception:** Heavy reasoning architectures (such as `gpt-5`) often refuse to output raw system tokens like `NO_RESPONSE_NEEDED`. For those models, use plain-language directives instead (e.g., "When the user says hold on, simply do not respond"). Review the [Prompt Situation Guide](/build/prompt-situation-guide#managing-pauses-and-hold-requests) for detailed reasoning model handling.</Note>
