## What is the Pronunciation Dictionary?

The pronunciation dictionary is an array attached to your agent configuration that intercepts specific text strings and forces the text-to-speech (TTS) engine to output an exact phonetic sequence. 

This is highly effective for correcting mispronounced technical jargon, regional dialects, and proprietary brand names.

Each dictionary entry requires three parameters:
* **Word or phrase:** The exact raw text string to intercept (e.g., `actually`).
* **Phonetic alphabet:** The supported phonetic notation system.
* **Phoneme:** The raw phonetic sequence written in that notation system.

### Phonetic Notations
| Alphabet System | API Code | Target Term | Phonemic Notation |
| :--- | :--- | :--- | :--- |
| International Phonetic Alphabet (IPA) | `ipa` | `actually` | `æktʃuəli` |
| CMU ARPAbet | `cmu` | `actually` | `AE K CH UW AH L IY` |
| Mandarin Pinyin | `pinyin` | `燕少飞` | `yan4 shao3 fei1` |
| Cantonese Jyutping | `jyutping` | `你好` | `nei5 hou2` |

<Note> **Tonal Notation:** When formatting tonal notations, use numerals `1–5` for Pinyin and `1–6` for Jyutping. Insert physical spaces between distinct syllables.</Note>

## Which Voices support Phonetic Alphabets?

Phonetic alphabet compatibility depends strictly on your active voice provider and selected model. Review the [supported languages by provider](/build/language-support#model-level-restrictions) guide for model-specific linguistic boundaries.

| Voice Engine / Model | Supported Alphabets |
| :--- | :--- |
| Tavly Platform Voices | IPA |
| Cartesia | IPA |
| Inworld | IPA |
| MiniMax `speech-2.8-turbo` | IPA, Pinyin, Jyutping |
| MiniMax `speech-02-turbo` | IPA, Pinyin |
| ElevenLabs `eleven_flash_v2` (English only) | IPA, CMU |
| ElevenLabs `eleven_flash_v2_5`, `eleven_multilingual_v2`, `eleven_v3` | Not supported |
| Fish Audio and OpenAI | Not supported |

**ElevenLabs Exception:** When an ElevenLabs voice is set to **Auto**, English agents resolve to Flash v2 (enabling IPA and CMU). Agents configured with other primary languages resolve to newer ElevenLabs models that do not accept pronunciation dictionaries. 

If you configure an alphabet that the assigned voice engine cannot interpret, Tavly safely stores the entry on the agent record without applying it to synthesized speech.

## What are the Dictionary Constraints?

The pronunciation dictionary operates as an open list on your agent without an arbitrary numeric ceiling enforced by the API. However, you must adhere to strict structural constraints.

* **Target selectively:** Restrict dictionary entries to technical jargon and proper names. Forcing phonemes onto common everyday words introduces highly unnatural acoustic artifacts.
* **Unique targets:** Every entry must declare a distinct `word` value. The API will reject payload updates containing duplicate target words.
* **Payload size:** Abnormally massive dictionaries increase the total JSON size submitted to the API. If requests approach payload limits, prune unused words.

## How do you configure it via API?

Tavly manages the dictionary directly on the root agent object via the `pronunciation_dictionary` parameter using the [Update Agent](/api-references/update-agent) endpoint, rather than using a standalone dictionary endpoint.

* Submit an array of items, each defining `word`, `alphabet` (`ipa`, `cmu`, `pinyin`, or `jyutping`), and `phoneme`.
* The submitted array **completely overwrites** previous dictionary records. To retain prior definitions, you must include them in the new payload.
* To clear all custom pronunciations, pass `pronunciation_dictionary: null`.

```json theme={"dark"}
{
  "pronunciation_dictionary": [
    { "word": "actually", "alphabet": "ipa", "phoneme": "ˈæktʃuəli" }
  ]
}
```
