## What are Platform Voices?

Platform Voices represent Tavly's native acoustic models engineered specifically for real-time phone calls. Each voice model accounts for natural conversational cadence, filler words, and prosody, while remaining highly legible across standard telecom audio codecs.

Unlike third-party voice engines, **Platform Voices include integrated failover redundancy**. If a primary synthesis route encounters an interruption, Tavly automatically routes traffic through a fallback model designed to perfectly mirror the original vocal identity. This entirely eliminates the need to set up rules inside your Security & Fallback Settings.

<Note> **Third-Party Limitation:** Third-party voices do not inherit automated failover. If you use external engines (like Cartesia or ElevenLabs), you must [configure TTS fallback](/build/tts-fallback) explicitly.</Note>

To evaluate how these native models perform alongside external alternatives, review the [TTS provider comparison](/build/tts-provider-comparison).

## How do you choose a Platform Voice?

You can assign Platform Voices directly from your core agent configuration interface.

1. Open your agent settings in the Tavly Dashboard.
2. Locate the primary voice selection control.
3. Test available models using the inline audio sample preview before saving your choice.

## How do you clone a Platform Model?

You can register custom speaker profiles that operate with native platform capabilities and inherit automated fallback resilience.

When submitting training requests to the [Clone Voice](/api-references/clone-voice) API, explicitly assign `platform` to the `voice_provider` parameter within your API payload. Cloned models created this way receive the exact same automated resilience as native voices, routing through internal fallback paths without manual configuration.
