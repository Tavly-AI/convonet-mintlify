## How do you build a multi-prompt agent?

You assemble a **Tavly multi-prompt agent** by strategically splitting the call into individual prompted states and explicitly wiring transitions between them. This approach, often used in lead-qualification flows, ensures highly predictable behavior by isolating logic to specific conversational phases.

</Frame>

<Steps>
  <Step title="Split the conversation into states">
    To begin, divide the call into logical phases. **Each distinct state gets its own dedicated prompt**, strictly scoped to handle just that specific part of the conversation without interfering with others.
  </Step>

  <Step title="Wire up transition logic">
    As seen in standard templates like "Lead qualification," a state's prompt explicitly specifies exactly when the agent should advance. For instance, you can instruct the agent to transition to `your_next_state` immediately once the caller responds "yes" to a targeted question.

    ```text
    7. Ask if user is interested in an in person tour.
     - if yes, transition to schedule_tour.
     - if no or hesitant, call function end_call to hang up politely and say will reach out if any other interesting properties pop up.
    ```
  </Step>

  <Step title="Decide when a function should fire">
    Just like transition logic, your prompt must specify the **exact moment to invoke a function**. By keeping tools scoped to specific states, you eliminate hallucination risks. For example, explicitly trigger `your_function_name` only when it is time to formally book an appointment.

    ```text
    3. Confirm the date, time, and timezone selected by user: "Just to confirm, you want to book the appointment at ...". Make sure this is a time from the available slots.
    4. Once confirmed, call function book_appointment to book the appointment.
    ```
  </Step>
</Steps>
