## What are MCP Tools?

**MCP Tools** allow you to point your AI agent at a remote [Model Context Protocol (MCP)](https://modelcontextprotocol.io/) server, instantly granting it the ability to call that server's tools during a live conversation.

Rather than building a separate [custom function](/build/single-multi-prompt/custom-function) for every single backend action, you connect to an MCP server once and autonomously decide which of its native tools the active agent is permitted to reach.

## When should you use an MCP server?

An MCP server is highly effective when the tools your agent requires are already securely sitting behind an MCP interface, or when you explicitly need to expose multiple scalable tools through one connection.

* **You already run an MCP server:** Directly reuse the exact tools your other agents and IDE assistants already utilize instead of rebuilding them completely as standalone custom functions.
* **You require multiple tools from a single integration:** Connect the server once, then selectively whitelist which tools the agent can access, bypassing the need to wire up individual API endpoints.
* **You are using a third-party MCP service:** Plug directly into a hosted MCP service (e.g., search, CRM, internal tooling) that inherently speaks the protocol.

If you strictly need to hit your own simple API endpoint, a [custom function](/build/single-multi-prompt/custom-function) is the more straightforward route. For isolated logic that requires no external server, utilize a [code tool](/build/single-multi-prompt/code-tool) instead.

<Note> This page explicitly covers connecting your agent **to** an external MCP server so it can utilize its tools. This differs entirely from [Tavly's own MCP server](/get-started/mcp-server), which allows external MCP clients (like Cursor or Claude Desktop) to manage your Tavly infrastructure natively.</Note>

### Example: Looking Up an Order via MCP

Say a retail support team already maintains an MCP server exposing `lookup_order` and `create_ticket` tools to their internal IDE assistants. You connect a Tavly support agent to that exact same server and authorize both tools. When a caller provides an order number, the AI inherently calls `lookup_order` and relays the live status back. If they report an issue, the agent actively calls `create_ticket`—no separate custom functions required.

## How does the integration work?

Once you successfully attach an MCP server to an agent, each explicitly enabled tool behaves identically to [custom functions](/build/single-multi-prompt/custom-function). The agent triggers them natively based on semantic prompts and tool descriptions.

Tavly securely reaches the remote server via Streamable HTTP, dynamically retrieves its list of available tools, and executes one by passing arguments inferred by the LLM based on the conversation context. Whatever structured data the tool returns is passed back to the agent, which can speak the payload aloud, act on it conditionally, or parse fields into explicit [dynamic variables](/build/dynamic-variables).

## How do you set up an MCP Server?

Connecting an MCP server involves configuring the base URL, defining authentication headers, explicitly mapping individual tools to the agent's function list, and testing the response payload.

<Steps>
  <Step title="Add the server">
    Inside your agent dashboard, open the **MCPs** section and actively click **Add MCP**. In the dialog, assign the server a descriptive **name** and provide its strictly formatted public **URL**.

    <Frame>
      <img src="https://mintcdn.com/retellai/M9QYKZE4hbt00HfL/images/mcp/add_mcp.png?fit=max&auto=format&n=M9QYKZE4hbt00HfL&q=85&s=13912eadf9db9240e285b4fcc1ac8326" alt="Add MCP dialog" width="698" height="621" data-path="images/mcp/add_mcp.png" />
    </Frame>
  </Step>

  <Step title="Add request headers (optional)">
    Under **Headers**, define exact key/value authentication pairs Tavly should dispatch along with the connection (e.g., `Authorization: Bearer <token>`). These values completely support [dynamic variables](/build/dynamic-variables) (e.g., `{{api_key}}`), enabling robust per-call authentication routing.
  </Step>

  <Step title="Add query parameters (optional)">
    Under **Query Parameters**, define specific key/value pairs that Tavly forcibly appends to the server's URL payload—highly useful if the backend strictly authenticates or routes requests utilizing query parameters.
  </Step>

  <Step title="Add a tool from the server">
    Click **Save** on the server configuration. Returning to the server list, click **Add Tools**. Under **Tool Access Scope**, open the **Select Tool** dropdown—Tavly connects securely to the server and lists its strictly available tools, complete with semantic names and descriptions.

    <Frame>
      <img src="https://mintcdn.com/retellai/cN2FgnKxD5bretb9/images/mcp/add_tool.png?fit=max&auto=format&n=cN2FgnKxD5bretb9&q=85&s=527d9b190bf9080d12b9fef2a9aea32e" alt="Add Tool dialog" width="738" height="589" data-path="images/mcp/add_tool.png" />
    </Frame>
  </Step>

  <Step title="Map response fields to variables">
    Under **Store Fields as Variables**, actively pull specific values out of the tool's returning JSON object and securely save them as [dynamic variables](/build/dynamic-variables) utilizing dot notation (e.g., `data.items[0].id`).
  </Step>

  <Step title="Set how the agent speaks around the call">
    Configure the agent's interaction flow:
    * **Talk While Waiting:** Instruct the agent to speak filler text (e.g., "Let me look that up") to explicitly fill the gap while the external tool executes.
    * **Talk After Action Completed:** Allow the agent to seamlessly begin speaking again once the external tool's result resolves.
  </Step>

  <Step title="Tell the agent when to call it">
    In the main agent prompt, dictate exactly when each explicitly enabled tool should be called. The agent strictly evaluates execution based on the tool's name, description, and your overarching prompt instructions.

    ```text theme={"dark"}
    When the user gives their explicit name and phone number, immediately call the `verify_user` tool to validate their account.
    ```
  </Step>
</Steps>

<Note> Conversation flow agents interact with MCP tools utilizing a dedicated [MCP node](/build/conversation-flow/mcp-node) rather than embedding them directly in the response engine, but the core server configuration behaves identically.</Note>

## Can I lock my MCP server down securely?

Yes. Tavly's outbound webhook traffic exclusively originates from the static IP address `100.20.5.228`. You must actively allowlist this address at your backend firewall, and you should implement a shared secret in the authentication headers for a secondary layer of cryptographic verification. Note that Tavly does not actively manage interactive OAuth flows; you must retrieve OAuth tokens independently and pass them natively via headers.
