---
title: 'Agent Transfer Tool : hand a call to another AI agent'
---

> Add the Agent Transfer (agent swap) tool to a Tavly single or multi-prompt agent so it can pass an in-progress call to a different AI agent without ending the conversation.

**Agent Transfer**, sometimes called **agent swap**, moves a live conversation from one AI agent to another while the call is still going. The agent taking over picks up with the full transcript and context already in hand, letting you divide a single call across several specialized agents without ever placing a phone-based transfer.

Typical uses include:

* Passing a caller from a front-desk agent to a booking-specific agent once their intent is clear.
* Switching to an agent built for a different language, based on what the caller prefers.
* Keeping each agent's prompt narrow and focused on one job, then linking them together (A → B → C) rather than maintaining one sprawling prompt.

## When This Tool Makes Sense

Reach for Agent Transfer when the goal is moving a caller **between AI agents on the same call**. It's useful for breaking a long or branching flow into pieces, reusing a specialized agent across different projects, or handling a language switch.

If the destination is a **person or an outside phone number**, use [call transfer](/build/single-multi-prompt/transfer-call) instead — Agent Transfer only moves between agents within Tavly.

Two kinds of agents can't be transfer destinations: agents running on a [custom LLM](/integrate-llm/overview), and chat-only agents. Attempting either causes the transfer to fail.

## Agent Transfer Compared to Call Transfer

Against routing to another agent through [call transfer](/build/single-multi-prompt/transfer-call), Agent Transfer has a few advantages:

* **Faster.** The swap happens almost instantly, with no new phone call to set up.
* **More reliable.** Since no new call is placed, there's no telephony failure to recover from.
* **No handoff script required.** The destination agent already has the entire conversation history, so the caller never has to repeat anything.
* **A single number works for every agent.** Agents on the receiving end of a transfer don't need their own dedicated phone numbers — one number can serve any number of agents.

Agent Transfer also works on **web calls**, not only phone calls.

## What Carries Over to the New Agent

The swap keeps everything under the same call — same `call_id`, and a single entry in [call history](/features/session-history). The receiving agent automatically gets:

* **The full conversation so far.** Everything said up to the point of transfer, so the new agent has exactly the context the caller does.
* **Call-level `metadata`.** Whatever was set on the original call — through [Create Phone Call](/api-references/create-phone-call) or the [Inbound Call Webhook](/features/inbound-call-webhook), for instance — is shared across every agent involved in the call.
* **Dynamic variables.** Both the `retell_llm_dynamic_variables` set when the call began, and anything [extracted mid-call](/build/single-multi-prompt/extract-dv), remain available to the new agent's prompt.

There's no dedicated "pass variables" setting on this tool — the shared call context described above handles that automatically. If you want the destination agent to act on a specific piece of information, [extract it into a dynamic variable](/build/single-multi-prompt/extract-dv) on the original agent, then reference it as `{{variable_name}}` in the destination agent's prompt.

## What Stays the Same and What Changes

A handful of call-level settings stay locked to whichever agent handled the call **first**, regardless of how many transfers happen afterward:

* **Recording access** (`opt_in_signed_url`) — whether recordings use signed or private URLs.
* **Data storage setting** (`data_storage_setting`) — what call data Tavly retains.
* **PII redaction** (`pii_config`) — the rules used for scrubbing PII after the call.
* **Denoising mode** — the audio denoising applied throughout the call.

Everything else tied to the active agent switches over with each transfer: **language, voice, ambient sound, LLM/model, prompt, tools, knowledge bases, boosted keywords, interruption sensitivity, and voice speed.** Two settings are opt-in exceptions — turning on **keep the same voice** or **keep the current language** carries that setting forward into the new agent instead of switching to its own. Keeping the same voice also preserves the current ambient sound.

Which agent's webhook fires is configurable per transfer (details in [Configuring the Tool](#configuring-the-tool) below) — by default, only the original agent's webhook is triggered.

  <Step title="Add the tool">
    In the **Functions** section, click **+ Add** and choose **Agent Transfer** from the list.

    </Frame>
  </Step>

  <Step title="Set the transfer options">
    Configure the following:

    * **Select agent** — which agent to hand the call to. Choose a specific version, or **Latest** so the transfer always targets whatever's currently published. Unless you opt to keep the current voice, the destination agent uses its own.
    * **Talk While Waiting** (optional) — when enabled, the agent fills any gap longer than roughly 2 seconds with a short line, something like "Let me get you to the right person." Write it as a prompt for the agent to phrase in its own words, or as fixed text to be read exactly.
    * **Post Call Extraction setting** — decides which agent's [Post Call Extraction](/features/post-call-analysis) configuration runs once the transfer completes. **Only transferred agent** applies the destination agent's entire analysis setup — its fields, model, and prompts. **Both this agent and transferred agent** merges the fields from both, with the destination agent's fields winning on any naming conflicts; running both adds to usage cost.
    * **Webhook setting** — controls which agent's [webhook](/features/webhook-overview) receives call events post-transfer: just the source agent, just the destination agent, or both. Defaults to the source agent only.
    * **Keep the same voice / keep the current language** (optional) — carries the current voice or language forward into the destination agent instead of switching to its defaults. Keeping the voice also keeps the current ambient sound settings.

## FAQ

<AccordionGroup>
  <Accordion title="Can a call be transferred more than once, or sent back to a previous agent?">
    Yes. Every destination agent has its own set of tools, including its own Agent Transfer tool, so you can chain multiple swaps together (A → B → C) or hand the call back to an earlier agent. There's no hard limit on how many transfers a single call can go through — the only restriction is that a new transfer can't start while one is already underway.
  </Accordion>

  <Accordion title="Will the caller notice the transfer happening?">
    Only if you want them to. The swap is nearly instant and stays within the same call. If you'd like the agent to say something during the handoff, turn on **Speak during execution**.
  </Accordion>

  <Accordion title="Does a transfer generate a new call or call ID?">
    No — it's still the same call, with the same `call_id`, showing up as a single entry in call history. The transcript, metadata, and dynamic variables all carry through the swap.
  </Accordion>

  <Accordion title="How is this different from agentic warm transfer, which also involves a second AI agent?">
    They address different situations, and the second AI agent is talking to a different party in each case.

    **Agent Transfer** swaps out which AI is speaking with *your caller*. No new phone call is placed — it's the same call, same `call_id`, with the conversation history flowing through. Use it to move between AI agents.

    **[Agentic warm transfer](/build/single-multi-prompt/transfer-call)**, on the other hand, is a mode of call transfer that places an actual outbound call to a phone number. Its transfer agent speaks with *whoever answers at that destination*, never with your original caller — who stays on hold the entire time. Use it to vet a human before connecting them.

    Once that transfer agent decides to bridge the call, the caller and destination connect directly and every AI exits. With Agent Transfer, by contrast, an AI remains on the call at all times.
  </Accordion>

  <Accordion title="What kinds of agents can't be transfer destinations?">
    Agents built on a [custom LLM](/integrate-llm/overview), and chat-channel agents. Attempting to transfer to either one fails, and the call simply continues with the current agent.
  </Accordion>

  <Accordion title="How does this tool show up in the API?">
    Its `type` is `agent_swap`, taking an `agent_id` and an optional `agent_version` (defaulting to the latest published version). Since the LLM sees the tool by whatever **name** you assign it, give it something descriptive — `transfer_to_appointment_agent`, for example.
  </Accordion>
</AccordionGroup>

<Note>
  Working in [Conversation Flow](/build/conversation-flow/overview) rather than a single or multi-prompt agent? Use the [Agent Transfer node](/build/conversation-flow/transfer-agent-node) — it behaves the same way, just configured as a node instead.
</Note>
