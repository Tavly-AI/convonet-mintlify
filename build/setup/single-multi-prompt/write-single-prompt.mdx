## How do you structure a single-prompt agent?

**Prompt design** is the most critical factor in your agent's overall performance. By structuring your Tavly single-prompt agent using explicitly **sectioned instructions** and **step-based tasks**, you ensure the agent handles edge cases smoothly, adheres to guardrails, and stays reliably on script throughout the entire call.

This page contains our recommended best practices for keeping agents on track. For working examples, open the Dashboard, start a new agent, and browse the available templates—each one is built from a real, production-ready prompt you can inspect and adapt.

## Why should you break prompts into sections?

Rather than writing one massive block of instructions, splitting your prompt into distinct, labeled sections (such as **Identity**, **Style**, **Rules**, and **Task**) drastically improves reliability. The model parses sectioned text more accurately, making your agent's responses more consistent and the prompt much easier to maintain.

Breaking your prompt down yields several direct benefits:

* **High reusability:** Sections like identity or tone can be seamlessly copied and reused across different agents.
* **Easier upkeep:** Modular prompts stay significantly easier to update or debug over time.
* **Better model comprehension:** The AI model has an easier time parsing which specific rules apply to which exact context.

```text
## Identity
You are a friendly AI assistant for Tavly AI. ....

## Style Guardrails
Be concise: ...
Be conversational: ...
...

## Response Guideline
Return dates in their spoken forms: ...
Ask up to one question at a time: ...
...

## Task
1. Greet the user
...
```

## How do you structure the core task?

When a call requires a specific procedure, lay the task section out as a strict **ordered list of steps** rather than a dense paragraph of instructions. This format gives the model clear direction on pacing, sequencing, and branching logic, explicitly preventing it from firing off every question in a single turn.

By embedding branching logic directly into the steps, you can dynamically send the conversation down different paths depending on the caller's answers.

```text
## Task
1. Ask for user's name.
2. Ask if user needs a refund, need a replacement, or just retrieving information.
  - if user needs a refund, transition to refund state.
  - if user needs a replacement, transition to replacement state.
3. If user is just retrieving information, ask for the order number.
...
```

## How do you force the agent to wait?

If your agent tends to advance too early, or if you need it to move through several instructions but pause at specific moments, you can be entirely explicit about pacing by inserting the exact phrase **`wait for user response`** directly into the step list.

```text
## Task
1. Inform user why you are calling.
2. Ask for user's name.

wait for user response

3. Ask if user needs a refund, need a replacement, or just retrieving information.

wait for user response
  - if user needs a refund, transition to refund state.
  - if user needs a replacement, transition to replacement state.


4. Ask for the order number.

wait for user response
...
```
