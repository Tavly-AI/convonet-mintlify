## What is the Send SMS tool?

The **Send SMS** tool empowers a Tavly single or multi-prompt agent to seamlessly transmit a text message while a live phone call is actively in progress. You can programmatically direct this SMS to the caller's native number or redirect it to a completely different destination.

<Note> This tool exclusively functions on numbers specifically provisioned with SMS capabilities, or on a pre-approved Tavly number. Review [enabling SMS](/deploy/enable-sms) for explicit setup details. </Note>

<Tip>Agents are not restricted to outbound messaging. They can autonomously **receive an SMS mid-call** and intelligently interpret the inbound payload, whether that consists of raw text, an image, audio, or video files. This functionality works automatically on Tavly Twilio numbers, and on custom telephony endpoints that have successfully cleared A2P approval. Review [Receive SMS during call](/deploy/enable-sms#receive-sms-during-call) for deeper technical implementation.</Tip>

## How do you pick a sending number?

When configuring the Send SMS tool, you must explicitly declare the outbound phone number. You can utilize a pre-approved Tavly pool number for rapid deployment, or use the agent's dedicated number for highly personalized, dynamic messaging.

There are two primary architectures for routing your outbound texts:

* **SMS-approved Tavly number:** This securely draws from a pool of numbers Tavly has already explicitly cleared for SMS use, bypassing the rigorous A2P 10DLC approval process entirely. The strict trade-off: the message body is locked to a **fixed template Tavly provides**, and it absolutely cannot be edited or dynamically driven by a prompt.
* **Agent's associated number:** This sends directly from the dedicated number attached to the agent itself. This route strictly requires your number to have achieved complete [A2P approval](/deploy/enable-sms#enable-sms-capabilities) for SMS routing. Furthermore, your agent must explicitly [collect the caller's consent](/deploy/sms-campaign-application#make-your-agent-collect-consent-the-same-way) before initiating any text message.

## How do you set the message content?

The content of your message depends entirely on the sending number you selected. You can leverage the LLM to generate dynamic text on an approved custom number, or rely on a static template if using the Tavly pool.

* **Sending from the agent's own number:** You can write a detailed prompt and let the agent autonomously decide what to say, or you can supply fixed text. Note that standard dynamic variables successfully resolve inside static text payloads.
* **Sending from an SMS-approved Tavly number:** The content payload is strictly locked to Tavly's unalterable preset template; there is no programmatic method to override or change it.

## How do you set the destination number?

By default, the outbound SMS automatically resolves to the caller's inbound phone number. However, you can explicitly redirect the payload elsewhere by supplying a fixed number, or by utilizing a dynamic variable such as `{{customer_phone}}`.

## How do you control agent speech during the SMS?

You can configure the agent to maintain conversational fluidity while the backend API request processes the text message. You can instruct the agent to speak during the SMS dispatch, and again immediately after delivery confirmation.

* **Speak While the Message Sends:** Enable this configuration to instruct the agent to say something brief while the network processes the outbound text. This auditory filler can be dynamically generated by a prompt or hardcoded as a fixed sentence.
* **Speak After the Message Sends:** Enable this to guarantee the agent explicitly confirms delivery once the SMS has successfully gone through. This is exceptionally handy for smoothly letting the caller know the message was successfully dispatched to their device.
