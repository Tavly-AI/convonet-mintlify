## What is the Extract Dynamic Variable tool?

The **Extract Dynamic Variable tool** securely grabs contextual values from the live conversation as an active call unfolds and securely saves them as [dynamic variables](/build/dynamic-variables) so the agent can reference them on subsequent conversational turns. 

For instance, a scheduling agent can automatically capture a caller's first name and email address immediately when spoken, utilize `{{user_name}}` while confirming the booking slot, and securely hand off `{{user_email}}` to a custom backend webhook that issues an appointment confirmation.

If you are developing a fixed conversation flow agent, utilize the [Extract Dynamic Variable node](/build/conversation-flow/extract-dv-node) instead.

## When should you use this tool?

You should reach for this tool whenever the active agent requires a spoken value again *later in the same exact call*—whether to personalize conversational responses, branch logic intelligently, or dynamically pass the value into a webhook function.

| Operational Need | Recommended Tool |
| --- | --- |
| Reuse a captured conversational value mid-call | **Extract Dynamic Variable tool** |
| Collect structured analytics only after the call ends | [Post Call Extraction](/features/post-call-analysis-overview) |
| Guarantee extraction occurs at a rigid sequence step | [Extract Dynamic Variable node](/build/conversation-flow/extract-dv-node) |
| Compute or transform an extracted numerical value | [Code Tool](/build/single-multi-prompt/code-tool) |

Because the LLM autonomously decides exactly when to call this tool based on context, there is absolutely no guarantee it fires at an exact fixed moment. If a value strictly must be captured in a sequential order, deploy a [conversation flow agent](/build/conversation-flow/extract-dv-node).

## How do you build the extraction tool?

Building the tool requires defining explicit variable names, writing precise descriptions that guide the LLM's entity extraction logic, defining explicit data types, and instructing the agent precisely when to trigger the extraction within the prompt.

<Steps>
  <Step title="Add the tool">
    In your agent's core **Functions** section, explicitly click **+ Add**, then select **Extract Dynamic Variable**.

    <Frame>
      <img src="https://mintcdn.com/retellai/rxvYffEkEJPRL1KD/images/extract-dv/dropdown.png?fit=max&auto=format&n=rxvYffEkEJPRL1KD&q=85&s=49f0432ef7c2341ae1d8f3c6db45cbaa" alt="Function-type menu" width="333" height="326" data-path="images/extract-dv/dropdown.png" />
    </Frame>
  </Step>

  <Step title="Give it a name">
    Assign a unique **Function Name** (1-64 characters) utilizing letters, numbers, underscores, or dashes strictly without spaces. Provide a succinct **Description** detailing what the tool captures overall.

    * **Function Name:** `extract_user_details`
    * **Description:** `Captures the caller's explicit name and email address.`
  </Step>

  <Step title="Define the variables to capture">
    Click **+ Add** under the **Variables** header and strictly configure each required data field:

    * **Variable Name:** The exact syntax you will reference later (e.g., `{{variable_name}}`).
    * **Variable Description:** What the precise value represents. The AI model relies heavily on this description to intelligently extract the correct entity.
    * **Variable Type:** Must be defined as `Text`, `Number`, `Boolean`, or `Enum`. Defaults to `Text`.
    * **Enum Options:** A strict set of allowed values required when utilizing the `Enum` type.

    <Frame>
      <img src="https://mintcdn.com/retellai/rxvYffEkEJPRL1KD/images/extract-dv/add-variable.png?fit=max&auto=format&n=rxvYffEkEJPRL1KD&q=85&s=1186a4aafcbfadd4702dd8579dcddb5b" alt="Variable editor" width="779" height="498" data-path="images/extract-dv/add-variable.png" />
    </Frame>
  </Step>

  <Step title="Tell the agent when to run it">
    Inject a clear, commanding instruction directly into the agent's main system prompt so the LLM knows definitively when to execute the extraction.

    ```text theme={"dark"}
    When the caller explicitly states their name and email address, immediately call extract_user_details to securely save the information before continuing the workflow.
    ```
  </Step>
</Steps>

## How do you choose a variable type?

Matching the declared type exactly to the kind of value you are capturing shapes precisely how the AI formats the extracted entity payload.

| Configured Type | Data Handled | Examples |
| --- | --- | --- |
| **Text** | Any spoken word or phrase string | `"headache"`, `"John Smith"` |
| **Number** | A purely numeric quantitative value | `42`, `98.6` |
| **Boolean** | A binary true or false condition | `true`, `false` |
| **Enum** | A strict value selected from **Enum Options** | `"yes"`, `"no"`, `"maybe"` |

Regardless of the configured type, every successfully extracted value is ultimately stored securely as a raw string literal. For example, a `Number` outputs as `"42"` and a `Boolean` translates to `"true"`. To convert these values back for mathematical operations inside a [Code Tool](/build/single-multi-prompt/code-tool), parse them explicitly (e.g., `Number(dv.order_count)`).
