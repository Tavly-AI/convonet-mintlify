## What is an SMS Node?

An **SMS Node** actively sends a text message during an active, ongoing phone call. The message dispatches instantaneously the exact moment the flow enters this node. You can securely route this text to the caller's own number or explicitly direct it to a completely separate destination.

<Note> **Telephony Requirement:** This node strictly functions only on telephony profiles with SMS explicitly enabled, or on a pre-cleared SMS-approved Tavly number. Read the [Enabling SMS Guide](/deploy/enable-sms) for provisioning details.</Note>

<Tip> **Inbound SMS capabilities:** AI agents aren't limited strictly to sending texts. They can also **receive an SMS mid-call** and natively interpret its content—including text, images, audio, and video. This functions automatically on Tavly Twilio numbers and custom A2P-cleared telephony profiles. Read [Receive SMS During Call](/deploy/enable-sms#receive-sms-during-call).</Tip>

## How do you configure the sender and content?

You dictate exactly which number the text originates from and what the message contains. Your choices dictate whether the message can be dynamically generated or if it remains locked to a compliance template.

* **Agent's associated number:** Sends the message directly from whatever specific number is bound to the agent. This requires the number to have successfully passed [A2P approval](/deploy/enable-sms#enable-sms-capabilities) for strict SMS compliance. The agent must successfully [collect human consent](/deploy/sms-campaign-application#make-your-agent-collect-consent-the-same-way) before this node ever executes.
  * **Content:** You can explicitly write a dynamic LLM **Prompt** to decide what to say, or utilize a **Static Sentence**. Dynamic variables actively work inside static content.
* **SMS-approved Tavly number:** Securely draws from Tavly's internal pool of numbers already cleared for SMS, instantly bypassing the lengthy A2P application process.
  * **Content:** The message body is strictly locked to a **fixed template** provided by Tavly to maintain legal compliance. It cannot be customized or driven dynamically by an LLM prompt.

## How do you set the destination?

By default, the SMS aggressively routes to the caller's own associated phone number. However, you can seamlessly redirect it elsewhere by defining either a hardcoded fixed number or a parsed dynamic variable such as `{{customer_phone}}`.

## When does the node transition?

The node transitions to the next sequential step the exact moment the SMS either successfully sends or fatally fails. This API response typically resolves in under 2 seconds. Which physical edge the flow traverses depends entirely on that exact success or failure outcome.

## What node settings are available?

The SMS Node provides targeted configuration options for global routing and model precision.

* **Global Node:** Transforms this node into a universally reachable destination from anywhere within the overarching flow. Read the [Global Node Guide](/build/conversation-flow/global-node).
* **LLM Override:** Explicitly assign a different underlying model strictly for this specific node, utilized for generating function arguments and potentially dictating the speak-during-execution filler message.
