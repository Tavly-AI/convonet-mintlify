## What is a Press Digit Node?

The **Press Digit Node** allows an active AI agent to silently navigate complex **Interactive Voice Response (IVR)** systems during outbound calls. The agent remains entirely silent while actively evaluating the telephonic menu to intelligently determine exactly which keypad digit to press. 

Every single time the IVR system finishes a spoken phrase, the node automatically re-evaluates the audio context to determine if a digit press is required. The exact timing of this evaluation is strictly shaped by the node's **detection delay** setting.

## How do you set up press digit behavior?

You must explicitly define exactly how the agent parses the IVR menu by writing rigid navigation instructions, configuring a proper audio detection delay, and mapping out structural transitions for success and failure states.

<Steps>
  <Step title="Write navigation instructions">
    Provide the agent with explicit guidance on exactly what keywords to aggressively listen for and which departments to actively avoid.

    **Sample prompt:**

    ```text theme={"dark"}
    Your goal is to reach the scheduling or appointments department.

    Preferred navigation keywords:
    • Scheduling
    • Appointments
    • New patients
    • Front desk

    Avoid:
    • Billing
    • Referrals
    • Medical records
    • Clinical departments

    If you are unsure which IVR option is correct:
    Choose the option most closely related to scheduling or appointments.
    ```
  </Step>

  <Step title="Set the detection delay">
    Since many legacy IVR systems speak slowly or pause awkwardly, setting a deliberate detection delay ensures the agent actively hears the entire menu before finalizing a decision. A delay of **1 second** is the recommended baseline starting point.
  </Step>

  <Step title="Set up transitions">
    Transitions evaluate and fire strictly whenever the IVR system stops speaking. You must thoroughly map out edges for both successful navigation and critical failure edge cases.

    * **Successful navigation:** Define a strict condition representing the target destination (e.g., `Reached scheduling department`). If the agent pressed the correct digit, the IVR's subsequent audio will confirm this state.
    * **Edge cases:** Actively account for getting stuck in infinite loops or dead ends. Use conditions like `Menu repeated 3 times` to forcefully break out of failing menus.

    **Example transition conditions:**

    ```text theme={"dark"}
    You've reached the scheduling department.
    ```
    ```text theme={"dark"}
    Menu repeated 3 times.
    ```
    ```text theme={"dark"}
    You've reached the wrong department or company.
    ```
    ```text theme={"dark"}
    You've reached an after-hours or voicemail message.
    ```
  </Step>
</Steps>

## What configurations are available?

The Press Digit node offers several advanced configurations to strictly govern how the LLM evaluates the audio stream and when the node becomes universally reachable.

* **Global Node:** Transforms this node into a globally reachable destination from anywhere else in the flow. Read the [Global Node Guide](/build/conversation-flow/global-node).
* **LLM Override:** Explicitly assign a different underlying language model strictly for this node to determine exactly whether and which digit must be pressed.
* **Fine-Tuning Examples:** Inject precise sample conversation transcripts to aggressively teach the agent how to perfectly handle specific IVR menu scenarios. Read the [Fine-Tune Examples Guide](/build/conversation-flow/finetune-examples).
