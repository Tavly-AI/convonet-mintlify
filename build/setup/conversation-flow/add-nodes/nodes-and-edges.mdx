## What are Nodes and Edges?

A conversation flow is essentially a graph—**nodes** linked together by conditional **edges**. 

Each node is strictly responsible for one discrete step of the call, whether that is handling dialogue, executing a backend tool, or transferring the session. Every edge carries a [transition condition](/build/conversation-flow/transition-condition) that explicitly governs when the agent moves to the next node.

Splitting the conversation into discrete nodes means you can tune, evaluate, and debug each step on its own, radically improving LLM reliability.

## How do you choose the Right Node Type?

Each node type is engineered for a specific task. You must pick the exact node that matches what that step of the call needs to accomplish.

### Nodes for Dialogue
* [**Conversation Node**](/build/conversation-flow/conversation-node): Handles pure back-and-forth dialogue with no tool calling involved. Transitions get evaluated dynamically after every user response.
* [**Subagent Node**](/build/conversation-flow/subagent-node): Handles dialogue while allowing the LLM to autonomously decide **whether and when** to execute available tools. If a tool absolutely *must* run at a given step deterministically, use a Function Node instead.
* [**Extract DV Node**](/build/conversation-flow/extract-dv-node): Silently pulls information out of the prior conversation and saves it as dynamic variables the moment the node is entered. It is not meant for direct dialogue.

### Nodes That Take Action
* [**Function Node**](/build/conversation-flow/function-node): Runs a single tool deterministically the exact moment the node is entered.
* [**Code Node**](/build/conversation-flow/code-node): Executes custom JavaScript natively inside Tavly's sandbox on entry. Good for formatting output or doing simple read-only lookups through `fetch()`.
* [**SMS Node**](/build/conversation-flow/sms-node): Sends a text message mid-call, either to the caller or a secondary number. *(Voice agents only.)*
* [**MCP Node**](/build/conversation-flow/mcp-node): Calls a tool on an external MCP (Model Context Protocol) server immediately upon entry.

### Nodes for Call Control
* [**Call Transfer Node**](/build/conversation-flow/call-transfer-node): Transfers the active phone call to another PSTN number or SIP URI. *(Voice agents only.)*
* [**Transfer Agent Node**](/build/conversation-flow/transfer-agent-node): Passes the conversation to an entirely different Tavly AI agent mid-call, inheriting full context without requiring a new phone number.
* [**Press Digit Node**](/build/conversation-flow/press-digit-node): Navigates an external IVR menu by autonomously emitting DTMF tones. *(Voice agents only.)*
* [**End Node**](/build/conversation-flow/end-node): Instantly terminates the call session. 

### Nodes for Logic and Structure
* [**Logic Split Node**](/build/conversation-flow/logic-split-node): Silently evaluates equations and branches the flow immediately upon entry without speaking.
* [**Subflow**](/build/conversation-flow/components): Bundles a reusable group of nodes into a single block on the canvas, allowing you to share complex logic chains across multiple agents.

## How do Nodes Link Together?

Every node (except the End Node) pushes the call forward through routing edges. 

* **Regular Edges:** Carry a specific transition condition—either a prompt the LLM evaluates or an equation built on dynamic variables.
* **Else Edges:** Act as a rigid fallback, firing instantly when no other condition is met. This ensures the flow never gets stuck.
* **Always Edges:** Transition unconditionally as soon as the user finishes their next turn.
* **Skip Response Edges:** Transition the moment the agent finishes speaking, without waiting for the caller to reply at all.

## Copying and Pasting Nodes

Nodes can be copied and pasted elsewhere on the canvas, into a different flow entirely, or even across browser tabs. Since Tavly uses your system clipboard, a copied node stays available across tabs and windows.

<Steps>
  <Step title="Select what you want to copy">
    Click a single node, or click and drag to select several nodes and sticky notes at once.
  </Step>

  <Step title="Copy it">
    Press `Cmd/Ctrl + C`. A **Copied** confirmation appears showing how many items were copied. Any sticky notes you selected, along with the tools attached to the selected nodes, get copied right along with them.
  </Step>

  <Step title="Paste it">
    Move your cursor to where you want everything to land and press `Cmd/Ctrl + V`. A **Pasted** confirmation shows up, and the nodes, notes, and tools appear at your cursor position, automatically nudged to avoid overlapping anything already on the canvas.
  </Step>
</Steps>

A couple of things worth knowing:

* If a copied tool already exists at the destination, it won't be duplicated — the pasted node just reuses the existing one.
* Component nodes can't be pasted inside a component editor. Trying to do so brings up a **Cannot Paste** message.

**Best Practices for the Canvas:**
* **Organize Automatically:** Click the **Organize** button to instantly clean up a cluttered, overlapping canvas.
* **Copy and Paste:** You can copy nodes (`Cmd/Ctrl + C`) and paste them (`Cmd/Ctrl + V`) elsewhere on the canvas, into a completely different flow, or even across distinct browser tabs.
* **Name Explicitly:** Always give your nodes descriptive names. Call transcripts display transition records based entirely on node names, making debugging past calls vastly easier when names are explicit.

## FAQ

<AccordionGroup>
  <Accordion title="When should I split a node into smaller pieces?">
    A few signs it's worth breaking a node down:

    * It's handling several complicated logic paths at once
    * The LLM starts struggling with consistency — hallucinating or giving off-base responses
    * Different parts of the step need different settings, like model or temperature
    * The flow as a whole becomes hard to follow or debug

    Splitting an overloaded node into smaller, more focused ones usually makes the whole flow more reliable.
  </Accordion>

  <Accordion title="How do I zoom in and out on the canvas?">
    Use your mouse's scroll wheel, or pinch on a touchpad.
  </Accordion>

  <Accordion title="Is there a cap on how many nodes I can add?">
    No — you can add as many nodes as your flow needs.
  </Accordion>
</AccordionGroup>
