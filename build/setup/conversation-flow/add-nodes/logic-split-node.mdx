## What is a Logic Split Node?

A **Logic Split Node** aggressively branches the conversation flow based on explicitly defined rules and dynamic variables. The AI agent evaluates these conditions silently and instantaneously the exact moment it enters the node, seamlessly routing the call to the appropriate destination.

Because the AI agent **does not speak** while inside this node, the operational time spent here is essentially negligible.

This node is exceptionally useful when you need to parse complex routing logic without overloading previous nodes. Handing an AI agent a massive stack of structural conditions all at once heavily degrades its decision-making accuracy. Breaking those choices apart using a dedicated logic split strictly keeps each conversational decision clean, focused, and reliable.

## When does the node transition?

The node transitions **immediately**. The precise moment the agent enters the Logic Split Node, it evaluates all attached logic conditions and natively routes the call forward without pausing.

## How do you configure branching logic?

Setting up branching logic requires adding standard transition conditions and explicitly defining a mandatory fallback route.

* **Add conditions:** Attach standard edge conditions exactly the same way you would on any other functional node. You can explicitly branch based on conversational context or parsed **[Dynamic Variables](/build/dynamic-variables)**.
* **Configure the Else Destination:** This node **always** requires a mandatory fallback destination. Because the Logic Split Node exists purely as a silent branching junction, this explicit fallback ensures the flow never fatally stalls if none of the defined conditions match the active context.

## What configurations are available?

The Logic Split Node offers advanced settings to make the node globally accessible and to rigidly fine-tune its routing intelligence.

* **Global Node:** Transforms the Logic Split Node into a universally reachable destination from anywhere within the overarching flow, acting as a centralized routing hub. Read the [Global Node Guide](/build/conversation-flow/global-node).
* **Fine-Tuning Examples:** Aggressively inject custom transition examples strictly isolated to this node to teach the LLM exactly how to interpret edge cases and trigger the correct routing destination. Read the [Fine-Tune Examples Guide](/build/conversation-flow/finetune-examples).
