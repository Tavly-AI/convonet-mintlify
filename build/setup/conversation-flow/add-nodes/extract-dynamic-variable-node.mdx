## What is an Extract Dynamic Variable Node?

An **Extract Dynamic Variable Node** strictly pulls contextual information directly out of the ongoing conversational dialogue and permanently stores it in memory as a reusable **[Dynamic Variable](/build/dynamic-variables)**.

Because this node serves exclusively as a silent data-processing junction, it is fundamentally **not** meant for holding spoken dialogue with the caller.

## How do you add a variable?

To securely extract a new variable from the dialogue, you must explicitly define its structural properties within the node settings to ensure the LLM parses the data correctly.

Configure the following fields:
* **Variable Name:** A strict, short programmatic label (e.g., `user_intent`) you will use to reference this value in future logic routing.
* **Description:** A highly explicit explanation instructing the LLM precisely what conversational context this value represents.
* **Variable Type:** The strict structural data type required for the variable.
* **Enum Options:** If the type is set to `Enum`, you must explicitly define the exact array of valid choices the LLM is permitted to extract.

## What variable types are supported?

Extracted variables must be mapped directly to one of four strict structural types to ensure backend data integrity for future API calls or logic routing.

| Data Type | Description | Valid Examples |
| --- | --- | --- |
| **Text** | Any unstructured string, word, or full sentence | `"headache"`, `"John Smith"` |
| **Number** | A strict numeric value (integer or float) | `42`, `98.6` |
| **Enum** | A strict value chosen exclusively from a predefined list | `"Yes"`, `"No"`, `"Maybe"` |
| **Boolean** | A rigid binary `true` or `false` | `true`, `false` |

## What node configurations are available?

This node offers targeted overrides to control exactly how the variable is extracted and how globally accessible the node becomes.

* **Global Node:** Transforms the extraction node into a universally reachable structural destination from anywhere within the overarching flow. Read the [Global Node Guide](/build/conversation-flow/global-node).
* **LLM Override:** Explicitly assign a distinctly different LLM specifically for this node to aggressively improve data-extraction accuracy and function-argument generation.
* **Fine-Tuning Examples:** Inject precise sample extraction transcripts strictly isolated to this node to forcefully teach the LLM exactly how to interpret edge cases. Read the [Fine-Tune Examples Guide](/build/conversation-flow/finetune-examples).
