## What is an Agent Transfer Node?

An **Agent Transfer Node** (often referred to as an **Agent Swap**) seamlessly hands an active call off from the current AI agent to a completely different, specialized AI agent. 

This node is critical for modularizing complex call flows. It allows you to build highly specialized agents (e.g., a front-desk screener and a dedicated appointment booker) and aggressively route the caller between them without relying on a rigid, traditional telephonic transfer. It is also exceptional for dynamically switching languages based on caller preference mid-call.

## Why choose Agent Transfer over Call Transfer?

Compared to routing to another agent via a traditional [Call Transfer Node](/build/conversation-flow/call-transfer-node), **Agent Transfers** provide massive architectural advantages:

* **Lower Latency:** The internal swap between agents happens almost instantaneously, far faster than establishing a new SIP connection.
* **Higher Reliability:** Because there is no new outbound phone call placed, there are zero external telephony fail points.
* **Shared Context:** The destination agent inherently inherits the full conversation history. There is no need for a clunky handoff message, and the caller never has to repeat themselves.
* **Cost Efficiency:** Destination agents do not require their own dedicated phone numbers. A single inbound number can seamlessly service an infinite number of specialized backend agents.

## What stays the same and what changes?

During a swap, strict call-level settings remain permanently locked to the agent that initially handled the call, while stylistic variables dynamically shift to the new agent.

**Settings locked to the original agent:**
* Recording access (`opt_in_signed_url`)
* Data storage settings (`data_storage_setting`)
* PII redaction (`pii_config`)
* Denoising mode

**Settings that shift to the new agent:**
Language, voice, ambient sound, LLM model, prompt, and tools all automatically switch to reflect the active destination agent. 

<Note> **Override Settings:** Activating **"Keep the same voice"** or **"Keep the current language"** will aggressively carry the original agent's stylistic settings into the destination agent. Preserving the voice inherently preserves the original ambient sound as well.</Note>

For exhaustive details on webhook routing, metadata inheritance, and dynamic variable handoffs, read the core [Agent Transfer Guide](/build/single-multi-prompt/transfer-agent).

## How do you set it up?

Configuring an Agent Transfer requires explicit assignment of the destination agent and defining post-call extraction behaviors.

<Steps>
  <Step title="Add the Agent Transfer node">
    Select **Agent Transfer** from the node canvas menu.
    <Frame>
      <img height="700" src="https://mintcdn.com/retellai/XoiOOpBkax1duk4y/images/cf/transfer-agent.png?fit=max&auto=format&n=XoiOOpBkax1duk4y&q=85&s=35f5316e53ababe990e132beeb4d2f3d" data-path="images/cf/transfer-agent.png" />
    </Frame>
  </Step>

  <Step title="Fill in the configuration">
    You must precisely define the handoff parameters:
    * **Transfer Agent:** Select the specific destination agent (and exact version) to route the call to.
    * **Speak During Execution:** Dictate whether the current agent delivers a transition phrase (e.g., `Let me get an expert for you`) while the swap processes.
    * **Post-Call Extraction:** Define exactly which agent's data extraction rules govern the end of the call. Choose **Only transferred agent** to strictly use the destination's model, or **Both** to actively merge extraction fields from both agents.
    <Frame>

    </Frame>
  </Step>
