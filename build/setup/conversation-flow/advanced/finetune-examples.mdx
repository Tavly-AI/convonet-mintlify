## What are Finetune Examples?

**Finetune Examples** are short, concrete conversation snippets attached directly to a specific node. The underlying model treats them as active few-shot demonstrations when evaluating responses and calculating logic transitions. 

They are the absolute most surgical tool available for resolving specific behavioral issues where the agent continuously misfires.

Every functional node supports two distinct types of fine-tuning:
* **Conversation Examples:** Teach the agent exactly how to respond natively within the node, dictating tone, phrasing, and critical information retention.
* **Transition Examples:** Teach the model exactly which outgoing edge condition to trigger given a specific, ambiguous snippet of conversation.

## How do you add a Finetune Example?

You inject these examples securely through the node's settings panel, actively pairing user inputs with the desired agent output or routing decision.

<Steps>
  <Step title="Select the Node">
    Click on the specific node on your canvas that is failing or misbehaving.
  </Step>
  <Step title="Locate Fine-Tuning">
    Scroll directly down to the **Fine-tuning Examples** section within the node's settings panel.
  </Step>
  <Step title="Add the Example">
    Click **+ Add example** and explicitly choose either **Conversation** or **Transition**.
  </Step>
  <Step title="Write the Transcript">
    Write out the verbatim example transcript. If creating a Transition example, aggressively map the transcript to the correct outgoing edge.
  </Step>
</Steps>

## When to use Conversation Examples?

Deploy **Conversation Examples** when the underlying model's replies are grammatically accurate but contextually off-target—such as rambling, failing to adopt a persona, or ignoring instructions to always include specific data.

**Example:** A closing node where the agent must strictly confirm an appointment time before ending the call.

```text theme={"dark"}
User: Okay, sounds good.
Agent: Perfect — you're confirmed for Thursday at 3 PM. Talk soon, goodbye!
```

**Conversation Best Practices:**
* Use raw, realistic transcripts rather than hyper-polished theoretical text.
* Keep every example extremely short and hyper-focused on the targeted behavioral flaw.
* Limit to **2-5 examples** per issue. Overloading the prompt does not inherently improve accuracy.

## When to use Transition Examples?

Deploy **Transition Examples** when the model consistently calculates the wrong logic and picks the wrong outgoing edge. You must pair a raw conversation snippet with the exact transition that should have fired.

**Example:** A node contains two edges: `User confirmed the appointment` and `User asked to reschedule`. If the model consistently misroutes ambiguous requests:

```text theme={"dark"}
User: Actually, can we move it to Friday?
Agent: Of course, let me check availability.
→ Transition: User asked to reschedule
```

```text theme={"dark"}
User: Yes, Thursday at 3 works for me.
Agent: Great, you're all set!
→ Transition: User confirmed the appointment
```

**Transition Best Practices:**
* Aggressively match the example to the exact phrasing pattern the model currently fails on.
* Target extreme edge cases: one-word answers, ambiguous phrasing, or polite deflections.
* Harvest real failures from the [Call History Transcript](/build/conversation-flow/debug-guide) to use as highly effective training data.

## What are the limits and best practices?

Finetune examples dynamically increase prompt complexity and token usage. They must be managed carefully to preserve latency.

| Symptom | Correct Fix |
|---|---|
| The agent says the right thing, but in the wrong tone. | Conversation example |
| The agent leaves out key information in its reply. | Conversation example |
| The agent transitions to the wrong node. | Transition example |
| The agent stays in the node when it should have moved on. | Transition example |
| The agent transitions too eagerly. | A transition example explicitly showing a case that should *not* trigger. |

* **Token Costs:** Finetune examples add tokens to **every single LLM call** executed within that node. Keep them ruthlessly brief to minimize latency.
* **Not a Crutch:** Use examples exclusively to fix observed failures—they are absolutely not a replacement for writing clear, logical node instructions.
* **Escalation:** If a problem persists despite adding 5+ examples, you must split the node into smaller chunks or upgrade to a more capable LLM. See the [Debug Guide](/build/conversation-flow/debug-guide).
