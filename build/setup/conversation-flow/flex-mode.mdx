## What is Flex Mode?

**Flex Mode** compiles an entire visual conversation flow into one unified, structured LLM prompt at runtime. It perfectly bridges the gap between the rigid, visual business logic of a flowchart and the fluid, dynamic handling of a single-prompt agent.

By compiling nodes, edges, and tools into a single prompt of executable Tasks, the agent gains the autonomy to navigate dynamically between tasks while strictly respecting the overarching global prompt.

<Warning> **Cost Impact:** Flex Mode can aggressively push your LLM costs up. Because instructions and tools from every node are compiled into one massive prompt, the total token count is significantly higher than in standard rigid mode. Once this combined prompt crosses 4,000 tokens, the [token scaling billing rule](/accounts/billing-exceptions#rule-2-llm-price-scaling-for--4000-token-prompt-length) activates, multiplying your baseline costs several times over.</Warning>

To aggressively optimize costs, stick with **rigid mode** or intelligently split your flow into smaller **[Subflows](/build/conversation-flow/components)** so fewer nodes compile into any single prompt.

## When does Flex Mode make sense?

Flex Mode is strictly recommended when you require the structural clarity of a flowchart but desperately need the conversational flexibility of a single prompt.

* **Fluid Context Shifting:** Context shifts seamlessly between different tasks. Effectively, every node behaves as a globally reachable node.
* **Multi-Intent Handling:** If a human caller completes multiple tasks simultaneously, the agent autonomously identifies and jumps to the next relevant task.
* **Non-Linear Continuity:** After switching context to a completely different part of the flow, the agent can logically resume the original task without repeating steps that are already completed.

## How does Flex Mode work?

You can activate Flex Mode either at the isolated **Subflow level** or globally at the **Agent level**.

* **Agent Level:** Converts every node in the entire flow into a single unified flex node. The agent behaves exclusively like a single-prompt agent until it explicitly hits an 'End Call' trigger.
* **Subflow Level:** Compiles only that specific subflow's internal nodes into one dynamic prompt. Everything outside of the subflow continues to execute as a standard, rigid conversation flow.

Turning it on at the agent level converts every node into a single flex node. The agent stays on that flex node, behaving essentially like a single-prompt agent, until it hits an 'End Call'.

Turning it on at the subflow level only converts that particular subflow's nodes into one prompt — everything outside it continues to run as a standard conversation flow.

## How do tools and functions differ?

Because Flex Mode mimics single-prompt behavior, it handles function tools differently than standard conversation flows.

* **Speak During Execution:** Functions exactly the same as rigid mode.
* **Speak After Execution:** This setting **does not exist** in Flex Mode. The agent inherently always speaks once a function finishes executing.
* **Wait For Result:** This setting **does not exist** in Flex Mode. The agent strictly waits for a function to complete before continuing, perfectly mirroring Single Prompt execution logic.

## Knowledge Base Behavior

Node-level knowledge bases are ignored entirely in Flex Mode. You'll need to configure your knowledge base at the agent level instead.

## What are the best practices and limitations?

Due to the complex nature of dynamic prompt compilation, you must adhere to strict architectural guidelines to prevent hallucinations.

* **Node-Level Knowledge Bases:** These are **ignored entirely** in Flex Mode. You must configure your knowledge base strictly at the global agent level.
* **Keep Instructions Concise:** Minimize node instructions so the LLM remains highly focused and token usage stays low.
* **Avoid Equation Edges:** Stick exclusively to Prompt edges. The LLM interprets deterministic equation conditions poorly when compiled dynamically, leading to erratic routing behavior.
* **Node Limits:** Using Flex Mode across more than **20 nodes** rapidly degrades performance and aggressively increases hallucination risks. Always split dense flows into smaller subflows.
* **Static Text:** The LLM will not always repeat static text instructions verbatim in Flex Mode due to its dynamic nature.
