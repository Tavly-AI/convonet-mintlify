## What are Subflows?

**Subflows** (previously known as Components) aggressively modularize conversational AI design. They allow you to package a specific subset of conversational nodes into a standalone, reusable mini-flow that can be seamlessly dropped into multiple different agents.

<Note> **Terminology Update:** Subflows were previously called **Components**. The underlying architecture and feature set remain entirely identical; only the nomenclature has changed.</Note>

**Why use a Subflow?**
* **Aggressive Reuse:** Build complex logic once and deploy it instantly across an infinite number of agents.
* **Guaranteed Consistency:** Ensure critical behaviors (e.g., identity verification or compliance scripts) execute identically across all use cases.
* **Canvas Cleanliness:** Hide dense routing logic inside a focused node rather than cluttering the primary agent canvas.
* **Centralized Iteration:** Update a shared Library Subflow once, and every single agent inheriting it is instantly upgraded.

## How do you manage and find Subflows?

Subflows are centrally managed directly within the agent builder dashboard, explicitly divided into global and local scopes.

From your agent's dashboard:
* Open the **Subflows** tab securely located in the left sidebar.
* You will immediately see two distinct architectural tiers:
  * **Library Subflows:** Shared globally at the account level. Usable by any agent.
  * **Agent Subflows:** Scoped strictly locally to the current active agent.

From your agent's builder in the dashboard:

* Open the **Subflows** tab in the left sidebar
* You'll see two sections:
  * **Library Subflows** — shared at the account level, usable across any agent.
  * **Agent Subflows** — scoped locally to just the current agent.

<Note>
  **Switching between flows:** the flow selector at the top of the builder (defaulting to **Main flow**) lets you move between your main agent, any subflows you have open, and transfer agents. Each opens in its own editor tab, and you can jump back to **Main flow** anytime.

## How do you create and integrate a Subflow?

You create a Subflow in an isolated editor tab, defining strict entry and exit points, before dropping it onto your main canvas as a single unified routing node.

<Steps>
  <Step title="Create the Subflow">
    Click the **+** button next to either **Library Subflows** or **Agent Subflows** to spawn a fresh editor tab.
    * The canvas initializes with a `Begin` node, a standard Conversation Node, and an `Exit Subflow` node.
    * You cannot nest a Subflow inside another Subflow.
  </Step>

  <Step title="Design the internal routing">
    Connect your structural logic securely between the entry and exit points.
    * **Crucial:** You must explicitly connect the `Begin` tag to the very first functional node.
    * **Crucial:** You must strictly wire up the `Exit Subflow` node; otherwise, the conversation will fatally stall inside the subflow with no escape route.

## What is the difference between Shared and Local Subflows?

The structural scope of a subflow strictly dictates which agents can access it and exactly who is affected when you deploy an update.

| Scope | Storage Location | Accessibility | Update Propagation | Best Used For |
| --- | --- | --- | --- | --- |
| **Library (Shared)** | Account-level record | Any agent globally | Instantly affects all agents using it | Universal compliance scripts, identity verification |
| **Agent (Local)** | Inside the agent | Only the parent agent | Only affects the parent agent | Highly specific, localized agent logic |

<Warning> **Publishing Risks:** Published agents can aggressively reference shared subflows. If you update a Library Subflow, it inherently alters the behavior of a locked, published agent. To protect a published agent, explicitly convert its subflows to Local before publishing.</Warning>

## What are the best practices for Subflows?

Designing reliable subflows requires strict adherence to modularity and clean data management.

* **Single Responsibility:** Give a subflow exactly one clear job (e.g., `Collect Shipping Address`).
* **Explicit Naming:** Name subflows aggressively using verb-noun pairs (e.g., `Verify Identity`).
* **Dynamic Variable Handoffs:** Safely pass data captured inside the subflow back to the main flow by writing to standard dynamic variables.
* **Test in Context:** A subflow implicitly inherits the global prompt of the main flow it is dropped into. Always execute your testing from the main canvas to simulate accurate end-to-end inheritance behavior.

## Best Practices

* **Keep each subflow focused** — give it one clear job, like "Collect Shipping Address."
* **Name it clearly** — combine an action with an outcome, such as "Verify Identity."
* **Design clean entry and exit points** — always set a start node, and include an end node so the flow can exit properly.
* **Reuse variables** — pass data captured inside the subflow back to the main flow using dynamic variables.
* **Test in context** — after inserting the subflow, open the Test panel to simulate the full end-to-end behavior.

## FAQ

* **How do I update a shared subflow used across multiple agents?**
  From within any agent, navigate to that subflow's edit page. Any change you make there applies everywhere the subflow is used.

* **Can I stop a change from affecting a specific agent?**
  Yes — turn off **Sync Updates** on that agent to convert its reference into a local copy instead.

* **What happens if I delete a library subflow?**
  Agents that were using it keep a local copy of their own, and simply stop syncing with the now-deleted library item.

* **Can I move a local subflow into the shared library?**
  Yes — switch **Subflow Access** to **Shared Library Subflow** to create a shared version and update the references accordingly.

* **Can subflows include tools or functions?**
  Yes. Subflows can contain function nodes and make use of your configured tools, behaving exactly as they would in the main flow. However, any tools used need to be defined within the subflow itself — they won't be visible at the agent level outside of it.

* **What happens if I forget to link the Begin node in a subflow?**
  It transitions to the next node based on whatever edges exist on the subflow node itself.
