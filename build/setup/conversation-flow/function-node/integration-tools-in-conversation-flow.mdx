## What are integration tools in conversation flow?

**Integration tools** in Tavly AI conversation flows enable agents to interact directly with external enterprise platforms like **Salesforce**, **HubSpot**, **Zendesk**, and **Cal.com** mid-call. Executed automatically upon entering a **function node**, Tavly AI handles all third-party authentication and API orchestration natively without requiring an intermediary server.

> Call HubSpot, Salesforce, Zendesk, or Cal.com tools from a function node inside a Tavly conversation flow, then branch the flow based on what comes back.

Within a conversation flow, integration tools execute through a dedicated [**function node**](/build/conversation-flow/function-node). As soon as the agent enters the node, the tool triggers deterministically, returning live payload data that steers the call's next step. Because Tavly AI manages all API connectivity and credentials, you do not need to host or maintain an intermediary webhook service.

### Integration tool runtime environments

Integration tools can be invoked across various structural components within the Tavly AI architecture:

| Component Type | Execution Behavior | Configuration Guide |
| :--- | :--- | :--- |
| [**Function Node**](/build/conversation-flow/function-node) | Executes deterministically immediately upon entering the node. | Attached directly inside the conversation flow canvas. |
| [**Subagent Node**](/build/conversation-flow/subagent-node) | The LLM dynamically decides whether and when to invoke the tool mid-dialogue. | Added alongside custom functions and tools. |
| [**Prompt Agents**](/build/single-multi-prompt/integration-tools) | Autonomous tool execution available across single- or multi-prompt architectures. | Managed via the dashboard Functions section. |
| [**Agent Workflow**](/agent/agent-workflow) | Runs actions outside the live call lifecycle (pre-call setup or post-call wrap-up). | Configured in call lifecycle automation workflows. |

For a comprehensive catalog of supported third-party providers, operational capabilities, and credential setup, see the [integrations overview](/integrations/overview).

## How do you add an integration tool to a flow?

To add an **integration tool**, first connect the target provider in the workspace **Integrations** dashboard or directly from the flow editor. Next, add a **function node**, select the desired tool from the categorized menu, configure fixed or conversational dynamic inputs, map response fields to **dynamic variables**, and test execution.

<Steps>
  <Step title="Connect the provider">
    Complete a one-time connection setup from the Tavly AI dashboard under the **Integrations** page at the workspace level. Detailed connection instructions are outlined in [connect a provider](/integrations/overview#connect-a-provider).
  </Step>

  <Step title="Pick the tool from the function menu">
    Inside the conversation flow canvas, add a function node. Tools belonging to connected third-party providers appear organized by provider name. 
    
    You can also select **Add integration** directly within this menu to authorize a new provider without leaving the conversation flow editor.

## How do you branch conversational logic based on tool results?

Conversation flows branch using **transition conditions** linked directly to the tool's execution payload. Because function nodes incorporate response payloads into transition timing, edges evaluate specific outcome criteria—such as **contact found** versus **no match**—routing callers to dedicated conversation nodes. Error and timeout states require explicit condition edges for safe handling.

To construct resilient branching logic:

* **Conditional routing**: Because function nodes factor the tool's result into their transition timing (see [when transitions happen](/build/conversation-flow/function-node#when-can-transition-happen)), configure [transition conditions](/build/conversation-flow/transition-condition) to branch on specific return data—such as creating one edge for a successful contact match and an alternative edge when no record exists.
* **Provider timeout windows**: Each integration tool call times out between **3 and 14 seconds**, depending on the specific provider and tool requested (accurate as of August 2026).
* **Dedicated error handling**: If a third-party tool call times out or encounters an API error, the flow continues advancing. Always create dedicated failure and timeout transition edges to handle fallback logic gracefully rather than allowing failures to cascade through default success pathways.

## Frequently asked questions

<AccordionGroup>
  <Accordion title="Do I need to host an API server to use integration tools?">
    No. Tavly AI manages all API requests, rate limits, and authentication handshakes directly with third-party providers like Salesforce, HubSpot, Zendesk, and Cal.com. No proxy server or custom middleware is required.
  </Accordion>

  <Accordion title="Can integration tools be executed by autonomous subagents?">
    Yes. In addition to deterministic execution inside a function node, integration tools can be mounted inside a [subagent node](/build/conversation-flow/subagent-node). In a subagent node, the LLM autonomously decides whether and when to trigger the tool based on conversation dialogue.
  </Accordion>

  <Accordion title="How should timeouts and third-party API errors be handled?">
    Third-party integration calls time out between 3 and 14 seconds depending on the connected provider. Because the flow will continue execution even if an error occurs, you should attach an explicit error edge to your function node to route the caller to a fallback conversation node.
  </Accordion>

  <Accordion title="Can I test an integration tool before deploying to a live call?">
    Yes. Inside the function node configuration panel, you can supply sample inputs and execute a live test run against your connected provider to verify authentication and field mapping before publishing the flow.
  </Accordion>
</AccordionGroup>
