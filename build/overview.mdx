> A map of everything that goes into a Tavly agent: agent type, speech understanding, response generation, voice, telephony edge cases, context, and guardrails.

An agent's behavior comes down to a handful of layers: how it interprets what the caller says, how it decides on a reply, how that reply sounds out loud, and how it handles moments that aren't a normal back-and-forth like voicemail, transfers, keypad input, and similar cases. This page walks through each layer so you know where to configure it. Begin with selecting an agent type and this choice determines which of the remaining settings actually apply to your deployment.

## What core functional layers define a Tavly AI voice agent?

Tavly AI voice agents operate across six core modular layers: speech understanding (ASR), response generation (LLM prompts and workflows), voice synthesis (TTS), telephony integration, dynamic contextual knowledge, and safety guardrails. Each layer functions independently, allowing developers to customize acoustic models, reasoning logic, dynamic variables, and conversational guardrails for reliable production deployments.

Understanding how these architectural layers interact allows development teams to build, optimize, and scale automated conversational voice pipelines:

| Agent Architecture Layer | Core Functional Responsibility | Primary Configuration Options |
| :--- | :--- | :--- |
| **Agent Modality & Architecture** | Determines conversational structure (voice telephony vs. text chat) | Conversation Flow, Single Prompt, Legacy Multi-Prompt, Chat |
| **Speech Understanding (ASR)** | Converts caller acoustic audio into real-time text tokens | Provider selection, language models, transcription mode, noise filters |
| **Response Generation (LLM)** | Reasons, selects tools, and crafts conversational dialogue replies | Agent Handbook, Conversational Mode, prompts, LLM parameters |
| **Speech Synthesis (TTS)** | Converts generated text responses into ultra-low-latency audio | Platform voices, custom voice clones, expressiveness, pauses |
| **Telephony & Edge Cases** | Manages PSTN/SIP signaling, media stream routing, and IVRs | Voicemail/AMD detection, DTMF touch-tones, custom SIP headers |
| **Context & Safety Guardrails** | Injects proprietary data and enforces compliance boundaries | Vector knowledge bases, runtime dynamic variables, safety guardrails |

## How do you choose between Voice Agent and Chat Agent architectures?

Tavly supports two foundational agent types: Voice Agents for real-time telephone or WebRTC conversations with acoustic turn-taking, and Chat Agents for text messaging across SMS, web widgets, and APIs. Voice agents branch into deterministic Conversation Flow state machines or rapid Single Prompt configurations tailored to specific conversational complexity.

An agent is built as either a **voice agent**, which handles live phone calls over PSTN or WebRTC, or a [**chat agent**](/build/create-chat-agent), which is text-only and reachable through the API, an embeddable website widget, or SMS. If you are building a voice agent, you will choose between two primary design approaches:

<CardGroup cols={2}>
  <Card title="Conversation Flow Agent" icon="brain-cog" href="/build/setup/conversation-flow/conversation-flow-overview">
    Design your call as a series of connected nodes with explicit transition logic. Suited to multi-step or high-stakes calls where behavior needs to stay predictable.
  </Card>

  <Card title="Single Prompt Agent" icon="sparkles" href="/build/setup/single-multi-prompt/prompt-overview">
    Describe the entire agent in a single prompt. Quickest path to a working agent, and well suited to simple, linear conversations paired with a small number of functions.
  </Card>
</CardGroup>

<Note>
  A **Multi-Prompt Agent** option also appears in the dashboard as a legacy path. It remains supported for agents already built this way, but new structured agents should be built on a conversation flow instead. If you're maintaining an existing multi-prompt agent, refer to the [single/multi-prompt overview](/build/setup/single-multi-prompt/prompt-overview).
</Note>

## How does Tavly interpret and transcribe caller speech?

Tavly automatically selects high-performance speech recognition ASR providers based on your configured languages. Developers can adjust dynamic transcription modes during live calls to balance latency against punctuation accuracy, while applying background noise filtering algorithms to suppress ambient acoustic interference and avoid mistaking background sounds for user speech.

Speech recognition forms the sensory foundation of the voice agent runtime:

- **Automated Engine Selection**: Tavly automatically provisions the optimal speech recognition [ASR provider](/build/understanding/asr-providers) based on the specific [languages](/build/language-support) configured for your agent.
- **Dynamic Transcription Tuning**: Fine-tune [transcription behavior](/build/understanding/transcription-mode) during active calls to prioritize real-time turnaround speed or rich grammatical punctuation.
- **Acoustic Noise Suppression**: Enable intelligent [background noise filtering](/build/understanding/handle-background-noise) to eliminate keyboard clicks, barking dogs, and ambient chatter so background noise is never misinterpreted as customer speech.

## How do you shape conversational response generation and LLM behavior?

Shape conversational reasoning by layering Agent Handbook policy presets over core prompts, configuring latency tiers and temperature in LLM options, and enabling Conversational Mode for natural vocal pacing. Follow prompt engineering guidelines to enforce strict turn-taking structure, dialogue flow boundaries, and speech-first output formats during calls.

Once speech is converted to text, Tavly orchestrates response generation through flexible language models:

- **Agent Handbook Presets**: Layer comprehensive [Agent Handbook](/build/response/agent-handbook) configurations to govern agent persona, factual precision, and safety policies without cluttering your core instructions.
- **Conversational Mode**: Activate [Conversational Mode](/build/response/conversational-mode) to encourage shorter, conversational phrasing, conversational fillers, and human-like backchanneling.
- **Prompt Engineering**: Follow the [prompt engineering guide](/build/response/prompt-engineering-guide) to structure multi-turn conversational trees, define function calls, and handle conversational edge cases.
- **Granular LLM Controls**: Configure [LLM options](/build/response/llm-options) to fine-tune model temperature, select ultra-low-latency fast-tier reasoning models, and enforce structured JSON output.

## How do you choose and tune synthetic speech voices?

Select from an extensive catalog of platform voices or integrate custom cloned voices. Fine-tune acoustic delivery by adjusting speech expressiveness, inserting natural breathing pauses, configuring patient silence waiting periods for hesitant callers, and assigning secondary TTS fallback providers to guarantee continuous voice synthesis during provider outages.

Vocal synthesis dictates how your agent connects emotionally with human callers:

- **Diverse Voice Libraries**: Select from curated [built-in platform voices](/build/speech/platform-voices) or integrate your own [custom voice](/build/speech/voice), including proprietary zero-shot cloned voices.
- **Expressiveness Tuning**: Adjust [expressiveness levels](/build/speech/expressive-mode) to match the operational context, from cheerful customer onboarding to calm emergency dispatch.
- **Speech Cadence & Pauses**: Inject natural timing using [inserted pauses](/build/speech/add-pause) for emphasis or number reading.
- **Patient Silence Wait**: Configure [silent waiting periods](/build/speech/no-response) so the agent remains attentive when a caller pauses to find information without interrupting them prematurely.
- **High-Availability TTS Fallback**: Designate an automated [backup TTS provider](/build/speech/tts-fallback) to ensure voice synthesis seamlessly switches over if an upstream voice vendor experiences degraded performance.

## How do you handle telephony edge cases like voicemails, transfers, and IVR menus?

Handle non-standard telephony events using automated answering machine detection (AMD) to navigate voicemail boxes, capturing DTMF touch-tone inputs from IVR phone menus, and passing enterprise session metadata via custom SIP headers. These controls ensure voice agents handle cold transfers, queue waits, and external telephony signaling reliably.

Production telephony environments present edge cases that standard chatbots never face:

- **Voicemail & IVR Detection**: Implement automated answering machine detection (AMD) to recognize [voicemail greeting tones and automated IVR phone menus](/build/telephony/handle-voicemail), allowing the agent to leave a targeted message or terminate the call gracefully.
- **Dual-Tone Keypad Input**: Capture [DTMF touch-tone input](/build/telephony/user-dtmf) directly from callers entering sensitive credit card details, extension numbers, or PINs.
- **Custom SIP Headers**: Pass session identifiers, CRM account tokens, and routing metadata between Tavly and your existing telecom carriers using [custom SIP headers](/build/telephony/sip-headers).

## How do you ground agents in dynamic data and enforce safety guardrails?

Ground voice agents in verifiable domain knowledge by connecting document, URL, or text-based knowledge bases, and pass personalized caller attributes at runtime using dynamic variables. Enforce automated safety guardrails to intercept jailbreak attempts, filter off-limits conversational topics, and substitute compliant fallback responses without dropping calls.

Ensure voice agents remain accurate, contextual, and compliant:

<Steps>
  <Step title="Connect Searchable Knowledge Bases">
    Link a managed [knowledge base](/build/context/knowledge-base) compiled from live website URLs, customer documentation PDFs, or raw text articles so the agent references factual answers rather than hallucinating.
  </Step>

  <Step title="Inject Per-Call Dynamic Variables">
    Feed real-time session parameters — such as a caller's first name, outstanding invoice balance, or CRM account ID — into your agent using [dynamic variables](/build/context/dynamic-variables).
  </Step>

  <Step title="Enforce Content Safety Guardrails">
    Enable automated [safety guardrails](/build/guardrails) to intercept unauthorized topics, adversarial prompt injections, and jailbreaks, seamlessly redirecting the dialogue to safe responses without terminating the call abruptly.
  </Step>
</Steps>

## Frequently asked questions about building Tavly AI agents

Building Tavly AI agents combines low-latency speech pipelines, adaptable LLM intelligence, enterprise telephony routing, and contextual data grounding into autonomous conversational systems. Whether designing structured Conversation Flow state graphs or rapid Single Prompt agents, developers configure modular speech, reasoning, and safety layers to deploy reliable voice automation.

<AccordionGroup>
  <Accordion title="What is the difference between a Voice Agent and a Chat Agent in Tavly?">
    **Voice Agents** are designed specifically for synchronous voice interactions over telephone networks (PSTN) and WebRTC. They include acoustic turn-taking, speech-to-text (ASR), and text-to-speech (TTS) pipelines. **Chat Agents** handle asynchronous or synchronous text messaging across SMS, embeddable web chat widgets, and direct API calls without audio processing overhead.
  </Accordion>

  <Accordion title="When should I choose a Conversation Flow Agent over a Single Prompt Agent?">
    Choose a **Conversation Flow Agent** when your business logic requires deterministic step-by-step branching, strict validation rules, or complex multi-turn workflows (such as healthcare intake, reservation scheduling, or identity verification). Choose a **Single Prompt Agent** when your conversational workflow is straightforward, conversational, and can be driven effectively with standard function calling.
  </Accordion>

  <Accordion title="How does Tavly maintain speech recognition accuracy in noisy environments?">
    Tavly pairs specialized ASR engines selected dynamically for your configured language with advanced background noise suppression algorithms. This ensures that environmental noise, such as office chatter, road sounds, or background music, is filtered out before audio reaches the language model.
  </Accordion>

  <Accordion title="How does Tavly prevent agent hallucinations and protect against jailbreaks?">
    Tavly combines dynamic data grounding via vector **Knowledge Bases** with real-time **Guardrails**. Knowledge bases supply the LLM with verified facts to prevent hallucinations, while automated guardrail filters monitor incoming caller inputs and agent outputs for prompt injections and off-limits subjects.
  </Accordion>
</AccordionGroup>
