> A map of everything that goes into a Tavly agent: agent type, speech understanding, response generation, voice, telephony edge cases, context, and guardrails.

An agent's behavior comes down to a handful of layers: how it interprets what the caller says, how it decides on a reply, how that reply sounds out loud, and how it handles moments that aren't a normal back-and-forth — voicemail, transfers, keypad input, and similar cases. This page walks through each layer so you know where to configure it. Begin with [selecting an agent type](#pick-an-agent-type) — that choice determines which of the remaining settings actually apply to you.

## Pick an agent type

An agent is built as either a **voice agent**, which handles live phone calls, or a [**chat agent**](/build/create-chat-agent), which is text-only and reachable through the API, an embeddable widget, or SMS. If you're building a voice agent, you'll then choose between two approaches:

<CardGroup cols={2}>
  <Card title="Conversation Flow Agent" icon="diagram-project" href="/build/conversation-flow/overview">
    Design your call as a series of connected nodes with explicit transition logic. Suited to multi-step or high-stakes calls where behavior needs to stay predictable.
  </Card>

  <Card title="Single Prompt Agent" icon="file-lines" href="/build/single-multi-prompt/prompt-overview">
    Describe the entire agent in a single prompt. Quickest path to a working agent, and well suited to simple, linear conversations paired with a small number of functions.
  </Card>
</CardGroup>

<Note>
  A **Multi-Prompt Agent** option also appears in the dashboard as a legacy path. It remains supported for agents already built this way, but new structured agents should be built on a conversation flow instead. If you're maintaining an existing multi-prompt agent, refer to the [single/multi-prompt overview](/build/single-multi-prompt/prompt-overview).
</Note>

## Interpret what the caller says

Tavly automatically selects a speech recognition [provider](/build/asr-providers) based on the [languages](/build/language-support) your agent is set up for. From there, you can adjust [transcription behavior](/build/transcription-mode) while a call is in progress, and set up [background noise filtering](/build/handle-background-noise) so ambient sound isn't mistaken for speech.

## Shape how the LLM responds

Beyond your core prompt, you can layer on [Agent Handbook](/build/agent-handbook) presets covering personality, accuracy, and safety, switch on [Conversational Mode](/build/conversational-mode) for more natural-sounding replies, and use the [prompt engineering guide](/build/prompt-engineering-guide) to handle structure and edge cases. [LLM options](/build/llm-options) expose model-level controls — temperature, fast-tier selection, and structured output among them.

## Choose and tune the voice

Select from [built-in platform voices](/build/platform-voices) or bring a [custom voice](/build/voice), including a cloned one. From there you can adjust delivery: [expressiveness](/build/expressive-mode), [inserted pauses](/build/add-pause), [silent waiting when the caller needs a moment](/build/no-response), and a [backup TTS provider](/build/tts-fallback) to fall back on if the primary provider fails.

## Handle non-standard call moments

Set up detection and handling for [voicemail boxes and IVR menus](/build/handle-voicemail), capture [DTMF touch-tone input](/build/user-dtmf) from callers, and pass data to other systems using [custom SIP headers](/build/telephony/sip-headers).

## Ground the agent in your data

Connect a [knowledge base](/build/knowledge-base) built from URLs, documents, or raw text so the agent can pull accurate information instead of depending solely on the prompt. Use [dynamic variables](/build/dynamic-variables) to feed in per-call details — a caller's name or account ID, for example.

## Add safety guardrails

Enabling [guardrails](/build/guardrails) lets the agent automatically detect off-limits topics in its own responses as well as jailbreak attempts coming from the caller, swapping in a safe response rather than hanging up or transferring the call.

## Test, then go live

Before launch, validate the agent's behavior using the [LLM Playground or simulation testing](/test/test-overview) tools. Once you're satisfied, [buy a phone number](/deploy/purchase-number) or [bring your own via SIP connection](/deploy/custom-telephony) to start taking calls.

Prefer managing agents through code? The [TypeScript SDK guide for agent creation](/get-started/create-agent-with-sdk) walks through building the response engine and agent, testing a draft version, and publishing it live.
