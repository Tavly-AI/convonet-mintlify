## Why do you need Scenario-Specific Prompts?

Standard text-to-speech engines frequently mispronounce dense data formats like URLs, acronyms, and phone numbers by attempting to read them as standard English words.

Structuring your prompts with explicit phonetic and formatting instructions forces the LLM to rewrite this data into a highly readable format before sending it to the TTS engine, ensuring your agent delivers clear, predictable spoken responses.

<Tip> **Automated Alternative:** You can entirely bypass manual prompting for these scenarios by enabling pre-configured templates (like Speech Normalization) directly in the [Agent Handbook](/build/agent-handbook).</Tip>

## How do you format Phone Numbers?

Text-to-speech engines often rush strings of digits. To insert deliberate pauses between number groupings, you must force the LLM to output hyphenated word representations using Tavly's *Read Slowly* capability.

Consult the [Speech Controllability documentation](https://docs.retellai.com/agent/speech-controllability#add-pauses-how-to-read-slowly) for underlying playback mechanics. Define clear formatting rules in your prompt so the model outputs digit strings with an identical cadence every time.

```markdown
If a caller inquires about contact numbers, provide: 4158923245

### Spoken Output Rules
Convert any incoming telephone format—including 4158923245, (415) 892-3245, or 415-892-3245—into word representations:
- Say: "four one five - eight nine two - three two four five"
- Keep a space on both sides of every hyphen to enforce natural pauses.
```

## How do you format Emails and Domains?

Spoken email addresses and URLs must be aggressively broken down into individual characters and explicit symbol terms to avoid voice synthesis failures.

Web domains often combine standalone acronyms with standard words. Instruct the model to parse each segment individually prior to synthesis.

### Email Parsing Instructions
```markdown
### Email Articulation Instructions
Standard input structure: name@company.com
Spell out the complete address character-by-character: n-a-m-e-@-c-o-m-p-a-n-y-dot-com
Voice the "@" symbol as "at".
```

### Domain Parsing Instructions
1. Separate the address into component chunks.
2. Read acronyms as individual letter names (translate "N" into "en" and "K" into "kay").
3. Read standard words using normal English pronunciation.
4. Explicitly voice the word "dot" ahead of any top-level domain suffix.

```markdown
### Domain Pronunciation Directive
Parse web URLs into phonetically clear spoken strings:
- "nklaundry.com" becomes "en-kay-laundry dot com"
- "abctest.net" becomes "A B C test dot net"
- "xyzco.org" becomes "ex-why-zee-co dot org"

Follow these segment splits strictly to prevent caller confusion.
```

## How do you handle Timestamps?

Enforce strict structural rules for time expressions in your prompt so the TTS synthesizer completely avoids ambiguous numeric output.

```markdown
### Date and Time Guidelines
- Render 1:00 PM as "One PM."
- Render 3:30 PM as "Three thirty PM."
- Do not output "O'clock"; format as "O-Clock".
- Every time expression must explicitly conclude with "AM" or "PM".
```

## How do you manage Hold Requests?

When a caller explicitly requests a pause (e.g., "hang on a second"), you must configure the agent to completely withhold spoken generation to prevent it from talking over the user.

### Standard (Non-Reasoning) Models
Tavly registers a pre-configured stop token: `NO_RESPONSE_NEEDED`. Emitting this string causes the system to terminate generation immediately without producing speech.

Add this direct instruction to your prompt:
```markdown
- If the caller asks you to hold or wait, respond only with: "NO_RESPONSE_NEEDED".
```

### Reasoning Models
<Warning> **Architectural Exception:** Heavy reasoning architectures like `gpt-5` do not reliably honor the `NO_RESPONSE_NEEDED` stop token. You must explicitly override this behavior using plain-language directives.</Warning>

For reasoning models, instruct the model directly within the system prompt:
```markdown
- When user says hold on, simply do not respond.
```
