## What is Voicemail & IVR Detection?

Voicemail and IVR detection are automated telephony features that classify when an outbound call connects to a machine endpoint—like an answering machine or a phone tree switchboard—rather than a live human. 

When executing [outbound calls](/deploy/outbound-call), Tavly monitors the early audio streams (within the first 3 minutes of a call). If it identifies a machine, it executes your configured routing policy, such as automatically dropping the call or transmitting an informative follow-up message.

<Note> **Touch-Tone Processing:** If you want your agent to process incoming DTMF keypresses from human callers, refer to the [Capture DTMF Input](/build/user-dtmf) documentation instead.</Note>

## How do you handle Voicemail endpoints?

You can configure the agent to either instantly terminate the line or hold in silence until the beep to read a pre-recorded message when a personal answering machine is detected.

<Steps>
  <Step title="Enable Voicemail Detection">
    Open your agent configuration, navigate to **Call Settings**, and turn on **Voicemail Detection**.
  </Step>

  <Step title="Select the Voicemail Action">
    Define exactly how the agent reacts upon identifying an answering service:

    * **Hang up if reaching voicemail:** Drops the call immediately upon detection, terminating even if the mailbox greeting is still actively playing.
    * **Leave a message if reaching voicemail:** Pauses until the recorded greeting completes and the beep/speaking turn is reached. It then recites one of two payload formats:
      * **Prompt:** Generates a dynamic message using LLM instructions (e.g., `Summarize the call and ask the user to call back.`).
      * **Static Sentence:** Reads an exact, hardcoded text string (e.g., `Hey {{user_name}}, sorry we missed you. Please call back.`). Fully compatible with [dynamic variables](/build/dynamic-variables).
  </Step>
</Steps>

## How do you handle IVR Disconnection?

IVR disconnection instructs the telephony engine to classify automated menus (such as corporate switchboards) and hang up the session automatically, ensuring your agent doesn't waste time talking to another machine.

<Note> **Navigating Phone Trees:** Automated IVR disconnection is completely separate from active [IVR Navigation](/build/single-multi-prompt/press-digit), which allows your agents to emit dual-tone multi-frequency (DTMF) digits to traverse complex phone systems.</Note>

To turn on automated menu termination:
1. Open your agent configuration.
2. Go to **Call Settings**.
3. Activate the **IVR Hangup** toggle.

## Operations & Latency Metrics

* **Detection Window:** The classification engine operates strictly during the initial 3 minutes of the connection.
* **Latency Impact:** Voicemail detection is architected for low-overhead telephony pipelines and typically contributes less than 30ms of operational latency.
* **Logging Verification:** Inspecting call session logs will explicitly display the [disconnection reason](/reliability/debug-call-disconnect). Answering machine terminations report `voicemail_reached`, while menu terminations record `ivr_reached`.

To turn on automated menu termination, open your agent configuration, go to **Call Settings**, and activate **IVR Hangup**.

## Frequently Asked Questions

<AccordionGroup>
  <Accordion title="Does voicemail detection work on inbound calls?">
    No. Machine and menu classification operates strictly during [outbound calls](/deploy/outbound-call), where the platform dials external numbers that may route to machines. On inbound calls, an outside party dials into your agent directly, so voicemail detection is inactive and has no operational effect.
  </Accordion>

  <Accordion title="The voicemail isn't being hung up even though hang up is enabled. What's wrong?">
    The destination system is likely classified as an IVR phone tree instead of a personal voicemail inbox. Because Tavly isolates voicemail and menu detection, voicemail hangup rules will not drop an IVR call. Activate **IVR Hangup** within your agent's **Call Settings** to handle and disconnect phone menus automatically.
  </Accordion>

  <Accordion title="Will voicemail or IVR detection run for the entire call?">
    No. The classification engine operates strictly during the initial 3 minutes of the connection. If your workflows require extended monitoring windows, contact [support@tavly.com](mailto:support@tavlyai.com).
  </Accordion>

  <Accordion title="Is there a latency impact when using voicemail detection?">
    Voicemail detection is architected for low-overhead telephony pipelines and typically contributes less than 30ms of operational latency.
  </Accordion>

  <Accordion title="How can I tell if a call reached a voicemail or IVR?">
    Inspecting call session logs will display the recorded [disconnection reason](/reliability/debug-call-disconnect). Answering machine terminations report `voicemail_reached`, while menu terminations record `ivr_reached`.
  </Accordion>

  <Accordion title="If the voicemail greeting keeps playing, will the agent hang up?">
    Yes. If configured to disconnect, Tavly drops the call instantly upon classification without waiting for the remote greeting audio to finish.
  </Accordion>

  <Accordion title="If the voicemail greeting keeps playing, will the agent leave a message?">
    No. When configured to leave a message, the agent holds silence until the remote greeting stops and the recording turn begins before voicing content.
  </Accordion>
</AccordionGroup>
