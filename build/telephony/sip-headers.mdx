## What are Custom SIP Headers?

Custom SIP headers allow external telephony carriers and [custom telephony](/deploy/custom-telephony) trunks to exchange application metadata directly with live Tavly sessions.

For example, your PBX can pass a caller account token or support ticket ID directly to the voice agent when initiating a session.

<Note> **Telephony Exclusivity:** SIP header exchange applies strictly to voice telephony connections. Tavly parses incoming headers on inbound calls, and applies configured headers during outbound dialing and call transfers.</Note>

<Warning> **Buffer Constraints:** Telephony middleboxes, session border controllers (SBCs), and SIP proxies typically enforce a **1024-byte buffer limit per header line**. Headers exceeding this length risk truncation or outright packet rejection.</Warning>

## How does Inbound Header Processing work?

On incoming telephony calls, Tavly automatically extracts any custom headers featuring an `X-` or `x-` prefix and injects them directly into the `call.custom_sip_headers` payload. 

Tavly strips the leading `X-` prefix and seamlessly maps each key directly into the session's [dynamic variables](/build/dynamic-variables) without requiring you to configure manual mapping rules.

### Header Extraction Example

Incoming SIP invitation headers:
```json theme={"dark"}
{
  "X-test-header": "something",
  "X-another-header": "something else",
  "from": "1234567890",
  "to": "0987654321"
}
```

Extracted `call.custom_sip_headers` and corresponding dynamic variables:
```json theme={"dark"}
{
  "test-header": "something",
  "another-header": "something else"
}
```

If an inbound call payload explicitly defines a dynamic variable matching an incoming header key, the explicitly supplied API value takes precedence over the parsed SIP header value.

## How do you set Headers on Outbound Calls?

When initiating outbound calls through the Tavly dashboard or API, you can easily attach arbitrary metadata headers. Every custom header key you define must begin with the `X-` prefix.

## How do you attach Headers to Call Transfers?

You can attach custom `X-` headers during mid-call transfers. Header values can incorporate dynamic variables, allowing your agent to dynamically forward information extracted during the call to the receiving party or downstream contact center.

To configure transfer actions based on your agent architecture:
* **Conversation Flow Agents:** Review the [Call Transfer Node](/build/conversation-flow/call-transfer-node#configure-transfer).
* **Single / Multi Prompt Agents:** Review the [Call Transfer Function](/build/single-multi-prompt/transfer-call).

<Warning> **Twilio Transfer Limitation:** Cold transfers routed to a target phone number execute via `SIP REFER`. Telephony carriers handle `REFER` metadata inconsistently. Notably, Twilio aggressively strips custom SIP headers from incoming `REFER` packets. If you use Twilio for telephony routing, custom SIP headers will not pass through cold transfers to external phone numbers.</Warning>
