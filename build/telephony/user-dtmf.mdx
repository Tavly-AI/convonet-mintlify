## What is DTMF Keypad Input?

DTMF (dual-tone multi-frequency) input allows callers to securely transmit numeric details using their physical phone keypad. When received, Tavly converts the keypad tones into text and feeds them directly into the conversation context for the language model to process.

Keypad entry offers a confidential and highly accurate method to collect sensitive data—such as security PINs, payment tokens, or verification codes—without requiring the caller to voice them aloud in public.

**Common Use Cases:**
* **Sensitive Credentials:** Submitting secure verification passcodes or account IDs.
* **Menu Branching:** Offering structured numeric IVR selections (e.g., "Press 1 to confirm, press 2 to modify").
* **Acoustically Challenging Environments:** Gathering clean numeric data when heavy background noise interferes with speech recognition.

<Note> **Outbound Detection:** If you are trying to detect outbound automated menus or answering machines, review the [Voicemail and IVR Handling](/build/handle-voicemail) guide instead.</Note>

## How do you configure Completion Rules?

You can govern exactly when the agent stops listening for digits and formulates a response by configuring three independent parameters within your agent's **Call Settings**. 

You can use these parameters individually or concurrently (e.g., stopping when the caller hits 4 digits *or* presses the pound key).

* **Digit Count Boundary (`user_dtmf_options.digit_limit`):**
  Sets the absolute upper threshold of digits accepted during a single turn (selectable from 1 to 50). The instant the caller enters this quantity of keys, Tavly marks the input as finished and prompts the agent.

* **Delimiter Key (`user_dtmf_options.termination_key`):**
  Designates a single key that instantly signals completion when pressed. Supported characters include numbers `0` through `9`, the hash/pound symbol (`#`), or an asterisk (`*`).

* **Inactivity Timeout (`user_dtmf_options.timeout_ms`):**
  Defines the idle window in milliseconds to wait following the most recent keypress before closing input (ranging from 1000ms to 15000ms). The timer resets with every newly received keypress.

## How do you prompt the Agent for DTMF?

To trigger keypad collection during a live call, you must explicitly instruct your agent within its system prompt to solicit touch-tone input from the user.

Instruct the model to solicit keypad presses clearly in your prompt architecture:
```markdown theme={"dark"}
Please punch in your account PIN on your phone keypad, followed by the pound key to submit.
```

When the user enters the digits, the captured DTMF tones appear directly in the conversation log as a recorded user turn:

## Debugging DTMF Failures

If digits the caller pressed are not showing up in the transcript:
1. **Verify Prompting:** Confirm that the agent explicitly instructed the caller to press keys. If the agent does not ask, the user may not know to use the keypad.
2. **Verify RFC 2833 Encoding:** Tavly strictly captures telephony tones conforming to RFC 2833 (out-of-band RTP telephony events). Inspect the SIP network capture to verify that the DTMF payload type negotiated in the SDP matches the RTP telephony event packets. For step-by-step instructions, see [Debug SIP calls using PCAP files](/reliability/debug-calls-pcap#extract-and-inspect-dtmf-events).

    Tavly captures telephony tones conforming to RFC 2833 (DTMF digits transmitted as out-of-band RTP telephony events). If digits fail to register, verify transmission encoding by [analyzing the call's PCAP file](/reliability/debug-calls-pcap#extract-and-inspect-dtmf-events) within Wireshark.
  </Accordion>

  <Accordion title="What happens if I set more than one completion option?">
    Tavly treats multiple completion parameters as concurrent conditions: the first condition met triggers completion. If you configure both a 4-digit limit and a 5-second timeout, receiving the 4th digit finishes collection immediately without waiting for the timeout.
  </Accordion>
