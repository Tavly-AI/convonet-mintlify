## What does the language setting control?

Configuring an agent's language directly controls the underlying speech recognition (ASR) mapping, outbound voice pronunciation, and the default dialect the LLM writes its responses in during a live call.

Specifically, the core language setting dictates:
* **Speech Recognition:** The precise dialect the agent uses to transcribe the live caller's speech.
* **Voice Pronunciation:** The linguistic rules the voice model uses when pronouncing written words and shaping its final accent.
* **Written Responses:** The agent automatically responds in this language natively, completely removing the need to add a "respond in X" instruction to your global prompt.

<Note> **Accent Control:** The specific voice model you select still carries the primary weight for the raw accent. The language setting simply refines the pronunciation rules and enforces the correct ASR model.</Note>

## Why choose a single language?

Sticking strictly to a single language yields the highest possible accuracy. The agent transcribes in one language, speaks with that dialect's native pronunciation, and replies predictably, removing all language detection guesswork.

<img src="https://mintcdn.com/retellai/SGc6xrwrS64ZRERp/images/language-single.png?fit=max&auto=format&n=SGc6xrwrS64ZRERp&q=85&s=bc78e8e6ff07f8516726414e9285f303" width="600" height="996" data-path="images/language-single.png" />

If you do not explicitly select a language, the agent will gracefully default to **English (US)**.

**Crucial Dependency:** Whatever voice model you pick *must* actually support your chosen language. The Tavly dashboard automatically hides incompatible combinations from the picker, providing an explicit tooltip detailing exactly which voice or model is causing the conflict.

## How do you support multiple languages?

If you need to serve a diverse customer base, you can deploy a Multilingual Agent or dynamically override the language on a strict per-call basis via webhooks.

<Card title="Configure a multilingual agent" icon="globe" href="/agent/multilingual">
  If your agent needs to serve callers speaking different languages, check out the multilingual guide.
</Card>

If your CRM already knows the caller's language before the call even connects, you should override the language via the [Inbound Call Webhook](/features/inbound-call-webhook). This grants you absolute single-language accuracy on every individual call without narrowing your overall customer reach.

<Note> **Closely Related Languages:** Speech recognition often struggles to differentiate closely related languages natively (e.g., Cantonese versus Mandarin Chinese). If your callers use these dialects, aggressively route them to single-language agents rather than relying on automatic detection. Read more about [closely related languages](/agent/multilingual#closely-related-languages-are-hard-to-distinguish).</Note>

## Which languages are supported?

A language must be explicitly supported by both your chosen Voice Provider (for text-to-speech) and at least one Speech Recognition Provider (for transcription) to function on Tavly.

Because provider coverage shifts dynamically, the dashboard itself serves as the definitive source of truth. Opening the language picker reveals the current live set of supported languages, updating instantly as you swap ASR or TTS providers. Incompatible combinations appear greyed out with descriptive tooltips.

* **Detailed Breakdowns:** Review [Language support by provider](/build/language-support).
* **Provider Comparisons:** Analyze the [TTS provider comparison](/build/tts-provider-comparison) and [Speech recognition providers](/build/asr-providers) documentation to evaluate trade-offs.

For locale-specific variants (e.g., British English vs. US English, or European Spanish vs. Latin American Spanish), the dashboard automatically exposes explicit dialect codes wherever supported by the underlying provider.
