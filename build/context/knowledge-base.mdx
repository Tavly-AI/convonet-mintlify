## What is a Knowledge Base?

Knowledge bases provide centralized document repositories that your Tavly agent references during active phone calls to pull factual answers in real time. 

Grounding agents with a knowledge base explicitly prevents hallucinations and supports comprehensive informational workflows—such as support desks, technical triage, and interactive FAQs—where the raw content is simply too large to fit in a static system prompt.

### Supported Ingestion Sources

* **Public Web Pages:** Ingested via direct URLs or path-based automated web crawlers.
* **Uploaded Files:** Comprehensive format compatibility (PDF, DOCX, TXT, CSV, HTML, Markdown, etc.).
* **Text Snippets:** Custom markdown or plain text blocks pasted directly into the dashboard.
* **Google Workspace:** Docs, Sheets, and Drive files synchronized via [Google Drive Sync](/integrations/google-drive-knowledge-base).
* **Microsoft OneDrive:** Storage files integrated via [OneDrive Sync](/integrations/microsoft-onedrive-knowledge-base).
* **Notion:** Workspace documentation synchronized through [Notion Sync](/integrations/notion-knowledge-base).

<Note> **Static Exports:** For documentation platforms lacking native cloud integrations (such as OneNote), export documents to PDF or Markdown and upload them as static files. Exported files do not synchronize automatically; you must re-upload documents whenever source materials change.</Note>

## How does Semantic Retrieval work?

When you attach one or more knowledge bases to an agent, Tavly triggers an automatic semantic retrieval process on every turn before the language model generates speech. You do not need to author custom prompt instructions or trigger manual tool calls.

1. **Ingestion & Indexing:** Uploaded resources are split into discrete chunks, mapped to vector embeddings, and securely indexed within a vector store.
2. **Contextual Query Synthesis:** Right before an agent speaks, Tavly synthesizes the recent conversational dialogue (excluding system instructions) into an isolated, standalone search query.
3. **Semantic Matching:** The synthesized query is matched against the vector database to extract the highest-scoring text passages.
4. **Prompt Augmentation:** Retrieved passages are instantly inserted into the model prompt under `## Related Knowledge Base Contexts`, providing strictly grounded facts for the upcoming reply.

### Automated Syncing and Web Crawling

* **Auto-Refreshing**: When active, Tavly polls URLs, Google Drive documents, OneDrive files, and Notion pages every 24 hours to sync updates. If a site is unreachable or a refresh times out before completing, previously indexed records remain active so agent operation is never disrupted. The dashboard displays the number of refreshed items.
* **Auto-Crawling**: For specified domain URL paths, Tavly discovers and indexes all sub-pages on a 24-hour cycle, bypassing any URLs explicitly designated on your exclusion list.

### Platform Limits

Each individual knowledge base operates within the following capacity boundaries:

* **Web URLs**: Up to 500 individual URLs.
* **Crawl Exclusions**: Up to 200 excluded URLs per crawl path; maximum 500 total excluded URLs per knowledge base.
* **Text Snippets**: Up to 50 custom text blocks.
* **File Uploads**: Up to 25 documents, capped at 50MB per file. Spreadsheets (.csv, .tsv, .xls, .xlsx) support up to 1,000 rows and 50 columns.

You can create multiple knowledge bases to bypass single-base limitations. Agents support connecting multiple knowledge bases concurrently.

## Structuring Content for Retrieval

* **Format documents as Markdown (`.md`)**: Structured Markdown delivers higher retrieval accuracy than unstructured `.txt` files.
  * Establish clear heading hierarchies (`##`, `###`) and keep individual sections concise. Subdivide long sections into smaller, distinct headers.
  * Rely on short paragraphs and bulleted items to isolate distinct rules.
  * For complex tables and graphics, accompany visual data with clear explanatory text to keep related facts within a single retrieved chunk.
* **Keep related facts colocated**: Group interrelated concepts inside the same section so chunks remain self-contained.
* **Write explicit references**: Specify concrete brand names, dates, numbers, and measurement units. Avoid detached relative pronouns like "it", "they", or "this" that depend on prior paragraphs.
* **Define narrow crawl paths**: Narrow URL targets perform faster and prevent exceeding exclusion list quotas.
* **Separate knowledge from instructions**: Populate knowledge bases strictly with reference data. Behavioral commands and voice tone belong in the agent's prompt.

## How do you Tune Retrieval Parameters?

You can calibrate the semantic matching sensitivity and chunk volume by selecting **Adjust KB Retrieval Chunks and Similarity** within the agent settings.

* **Chunks to Retrieve:** Sets the upper limit of text blocks passed per turn (slider 1–10; default: 3). Increasing chunk volume gives the model broader context but expands prompt length and can degrade reasoning speed.
* **Similarity Threshold:** Sets the semantic similarity bar for a chunk to match (slider 0.00–1.00; default: 0.60). Higher values restrict results to near-exact semantic matches.

The baseline default (3 chunks / 0.60 threshold) works optimally for standard voice interactions.

Use this panel to debug retrieval issues:
* **Missing context**: If the agent lacked necessary data, verify whether the correct passage was retrieved. If absent, increase **Chunks to retrieve**, lower the **Similarity Threshold**, or restructure source documents (see [Best practices](#best-practices)).
* **Ignored context**: If the right passage was retrieved but omitted from speech, refine instructions in your main agent prompt.
* Chat agents feature the same retrieval logs within [Chat History](/features/session-history).

## Frequently Asked Questions

<AccordionGroup>
  <Accordion title="Do I need to change my prompt to use knowledge base?">
    No. Once a knowledge base is linked to an agent, semantic retrieval executes automatically before each turn.
  </Accordion>

  <Accordion title="How can I prevent the LLM from generating information not found in the knowledge base?">
    Enforce strict grounding by adding explicit negative constraints to your prompt:

    ```
    Only answer using the information in ## Related Knowledge Base Contexts.
    If ## Related Knowledge Base Contexts is missing or does not contain relevant information, respond:
    "There is no related information in knowledge base."
    ```
  </Accordion>

  <Accordion title="The agent response is not correct, what should I do?">
    Check the source document to verify that the factual answer is present. Ensure files follow recommended formatting guidelines with descriptive headings and clean Markdown paragraphs.
  </Accordion>

  <Accordion title="Will this add a long latency to the call?">
    Tavly's retrieval pipeline is optimized for real-time voice streaming and typically completes in under 100ms.
  </Accordion>

  <Accordion title="Will the knowledge base name influence the retrieval?">
    No. Knowledge base titles are administrative labels and are excluded from the retrieval index.
  </Accordion>

  <Accordion title="What happens if a source fails to process?">
    Processing errors on individual files do not break the rest of the knowledge base. The system processes all valid files, while failed items appear in the console under **Some knowledge base sources could not be processed:**.

    If an entire knowledge base fails parsing, its status displays **Failed** alongside **Failed to process the knowledge base:**.

    Dismiss warnings by selecting **Ignore**. To recover a failed file, resolve the underlying issue (such as unblocking a URL or resizing an oversized document) and re-upload.
  </Accordion>

  <Accordion title="What happens if an auto-refresh can't finish?">
    Automatic refresh operations never delete or overwrite existing data when updates fail. If an individual file or page cannot sync, Tavly retains the previously indexed version and logs **Refresh completed with N errors. Existing content was retained for sources that could not be refreshed.**

    If a scheduled refresh job reaches its processing time limit, unreached documents remain active with the notice **Refresh reached its time limit after processing X of Y sources. The remaining sources were retained unchanged.**

    The engine automatically retries sync operations during the next 24-hour cycle. Click **Ignore** to dismiss the notice.
  </Accordion>

  <Accordion title="What does the Knowledge Base Instruction (focus areas) setting do?">
    Tavly condenses recent dialogue into a standalone search query before querying vector stores. The Knowledge Base Instruction supplies explicit guidance for this query-generation step (such as emphasizing specific terms or domains). It steers what search terms are formed, rather than filtering returned chunks. This setting is optional, accepts up to 500 characters, and can be overridden per node in Conversation Flow agents.
  </Accordion>
</AccordionGroup>
