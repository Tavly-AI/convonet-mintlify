## What are Dynamic Variables?

Dynamic variables allow you to pass runtime data directly into your agent's conversation loop on a per-call basis. Using the `{{variable_name}}` placeholder syntax, you can deliver individualized interactions across customer segments while preserving a unified flow architecture.

**Primary Use Cases:**
* **Customer Greetings:** "Welcome back, `{{customer_name}}`. How can I assist you?"
* **Transactional Context:** "I have your record pulled up for account `{{account_id}}`."
* **Conditional Routing:** Forward calls to designated regional numbers based on `{{department_queue}}`.
* **Schedule Verification:** Confirm dates dynamically via `{{appointment_date}}` or `{{delivery_window}}`.

## Where can you use Dynamic Variables?

You can embed dynamic variable placeholders across numerous platform components, and Tavly will resolve them instantly when a call connects.

* **System Prompts:** Core agent behavioral instructions, guardrails, and role descriptions.
* **Begin Message:** The initial spoken greeting delivered when a call connects.
* **Tool & Function Definitions:** Endpoint URLs, tool descriptions, and JSON parameter descriptions.
* **Call Control Policies:** Voicemail greetings, transfer target phone numbers, and warm transfer handoff summaries.
* **Event Webhooks:** Query strings and paths in agent-level webhooks (e.g. `https://example.com/webhook?call_for={{customer_name}}`).

## How do you Configure Variables?

<Steps>
  <Step title="Embed Placeholders">
    Declare variables anywhere in your prompts using double curly braces:
    ```json theme={"dark"}
    "Hello {{user_name}}, I understand you're interested in {{product_name}}. How can I help you today?"
    ```

    Supported text inputs include an interactive **variable picker**:

    1. Enter **`{{`** in any supported input. A popup menu appears displaying available system, agent, and flow variables.
    2. Narrow candidate items by typing search characters.
    3. Press **Enter**, **Tab**, or click an entry to automatically insert the complete placeholder (e.g. `{{customer_name}}`).

    <Note>
      The autocomplete picker is an optional convenience. You can type `{{variable_name}}` manually at any time. Whitespace within braces is automatically trimmed during resolution.
    </Note>
  </Step>

  <Step title="Test and Simulate Variable Resolution">
    Verify that placeholders resolve accurately using the dashboard test panel before deploying changes. You can assign mock values in [simulation test cases](/test/llm-simulation-testing) to ensure automated evaluations test real-world scenarios.

    <Frame>
      <img height="700" src="https://mintcdn.com/retellai/rxvYffEkEJPRL1KD/images/dynamic.png?fit=max&auto=format&n=rxvYffEkEJPRL1KD&q=85&s=d7fd0be7594df5ff87f27d5d551b03fb" alt="Testing dynamic variables in dashboard" data-path="images/dynamic.png" />
    </Frame>
  </Step>

  <Step title="Establish Agent-Level Fallbacks">
    Configure agent-level default values in your agent settings. Default values act as fallback parameters whenever a specific variable key is completely omitted from an incoming API call or webhook payload.

    <Frame>
      <img height="700" src="https://mintcdn.com/retellai/rxvYffEkEJPRL1KD/images/dynamic-default.png?fit=max&auto=format&n=rxvYffEkEJPRL1KD&q=85&s=38eebb99b95332428477860824d46e71" alt="Default dynamic variable values in agent settings" data-path="images/dynamic-default.png" />
    </Frame>
  </Step>

  <Step title="Inject Variables into Live Calls">
    **For Outbound Telephony:** When dispatching calls using the [Create Phone Call](/api-references/create-phone-call) endpoint, pass your variables inside the `tavly_llm_dynamic_variables` payload dictionary.

    ```json theme={"dark"}
    {
      "user_name": "John Smith",
      "product_name": "Premium Plan",
      "account_status": "active"
    }
    ```

    ### Inbound Telephony

    Supply dynamic attributes dynamically via the [Inbound Call Webhook](/features/inbound-call-webhook) response when a call hits your number.
  </Step>
</Steps>

<Warning>
  All property values inside `tavly_llm_dynamic_variables` must be submitted as strings. Numeric, boolean, and nested object types are unsupported (pass numbers as `"42"` and booleans as `"true"`). When accessing variables inside a [Code Tool](/build/single-multi-prompt/code-tool) or [code node](/build/conversation-flow/code-node), cast them explicitly prior to comparison (e.g. `Number(dv.order_count)`, `dv.is_member === "true"`, or `JSON.parse(dv.items)`).
</Warning>
## What System Variables are built-in?

Tavly automatically populates essential runtime variables for every session without requiring you to manually pass them.

| Variable | Definition | Output Sample |
| :--- | :--- | :--- |
| `{{current_agent_state}}` | Active state identifier (multi-state agents) | `"greeting"` |
| `{{previous_agent_state}}` | Preceding state identifier (multi-state agents) | `"qualification"` |
| `{{current_node}}` | Active node label (Conversation Flow agents) | `"greeting"` |
| `{{previous_node}}` | Preceding node label (Conversation Flow agents) | `"qualification"` |
| `{{current_time}}` | Current time in `America/Los_Angeles` | `"Thursday, March 28, 2024 at 11:46 PM PST"` |
| `{{current_time_[timezone]}}` | Current time in a target timezone (e.g. `{{current_time_Australia/Sydney}}`) | `"Thursday, March 28, 2024 at 11:46 PM AEDT"` |
| `{{current_hour}}` | Fractional decimal hour in `America/Los_Angeles` | `"3.5"` |
| `{{current_hour_[timezone]}}` | Fractional decimal hour in target timezone | `"3.5"` |
| `{{current_calendar}}` | Rolling 14-day date calendar in `America/Los_Angeles` | Schedule string listing dates relative to today |
| `{{current_calendar_[timezone]}}` | Rolling 14-day date calendar in target timezone | Localized date list relative to today |
| `{{session_type}}` | Channel category | `voice` or `chat` |
| `{{session_duration}}` | Elapsed call duration in human-readable units | `"20 minutes 30 seconds"` |
| `{{session_duration_ms}}` | Elapsed call duration in integer milliseconds | `"1230000"` |

<Note>
  Timezone qualifiers form part of the variable key itself, rather than an independent argument. To set timezones per session dynamically, rely on [nested variables](#nested-variables): place `{{current_time_{{my_timezone}} }}` in your prompt and submit `my_timezone: "America/Los_Angeles"` at session start.
</Note>

### Voice Call Metadata

Available exclusively during voice phone calls:

| Variable | Definition | Output Sample |
| :--- | :--- | :--- |
| `{{direction}}` | Call origin orientation | `inbound` or `outbound` |
| `{{user_number}}` | Caller telephone number (origin on inbound; target on outbound) | `+12137771234` |
| `{{agent_number}}` | Agent telephone number (target on inbound; origin on outbound) | `+12137771235` |
| `{{call_id}}` | Global call session identifier | `call_12345678906eaa0222bd3dd2a6c` |
| `{{call_type}}` | Transport protocol | `web_call` or `phone_call` |

### Chat Metadata

Available exclusively during chat interactions:

| Variable | Definition | Output Sample |
| :--- | :--- | :--- |
| `{{chat_id}}` | Global chat session identifier | `chat_12345678906eaa0222bd3dd2a6c` |

### Post-Session Analytics

Populated after a session terminates and accessible by post-call hooks in your [agent's workflow](/agent/agent-workflow): `{{call_summary}}`, `{{call_successful}}`, `{{user_sentiment}}`, `{{disconnection_reason}}`, and `{{call_status}}`, alongside custom attributes extracted via [Post Call Extraction](/features/post-call-analysis-overview). For chat agents, equivalent attributes include `{{chat_summary}}`, `{{chat_successful}}`, and `{{chat_status}}`.

### CRM Contact Variables

If a phone number matches a stored record in [contacts](/features/contacts), Tavly exposes contact parameters: `{{first_name}}`, `{{last_name}}`, `{{do_not_call}}`, and any custom contact fields. If no matching record is found, these values remain unpopulated. Review [contact memory](/integrations/build-contact-memory) to populate these fields from historical conversations.

## Nested Variable Evaluation

Tavly supports recursive substitution, where the output of an inner variable forms the identifier for an outer variable:

```
{{current_time_{{my_timezone}} }}
```

If `my_timezone` is provided as `"America/Los_Angeles"`, Tavly resolves the inner token to produce `{{current_time_America/Los_Angeles}}`, which then evaluates to the localized system timestamp.

<Note>
  Nested evaluation refers to recursive string interpolation, not JSON dot-notation traversal. Because variable dictionaries require flat string structures, objects like `{"client": {"name": "Mario"}}` cannot be referenced as `{{client.name}}`. Flatten objects into discrete strings (e.g. `client_name: "Mario"`) instead.
</Note>

## Managing Unset and Missing Variables

### Unset Resolution Rules

When an active call omits a dynamic variable without a default fallback:

* **Missing key or `null`**: The placeholder is left untouched with literal curly braces intact (`"Hello {{user_name}}"`).
* **Empty string (`""`)**: The token is treated as an intentional blank value and is stripped cleanly (`"Hello "` without braces).
* **Populated value**: The token is substituted with the supplied string (`"Hello John"`).

<Note>
  An empty string (`""`) counts as an explicit value, overriding agent-level defaults. To trigger an agent-level default fallback, omit the variable key entirely or supply `null`.
</Note>

### Detecting Missing Values

#### Conversation Flow Equations

In conditional branch rules:

```
Equation: {{user_name}} exists
Result: Evaluates to True if the variable is defined (including empty strings)
```

#### Prompt Guardrails

In system instructions, author conditional logic to protect against unpopulated braces:

```markdown theme={"dark"}
If {{user_name}} appears with literal curly braces, use a generic greeting like "Hello there".
Otherwise, address the customer directly using {{user_name}}.
```

### Best Practices

1. **Assign agent-level fallbacks**: Configure baseline values in settings for non-critical fields.
2. **Apply defensive prompt framing**: Structure dialogue instructions to remain natural whether values resolve or remain blank.
3. **Verify edge cases in sandbox testing**: Evaluate agent responses against both populated and missing payload keys.
4. **Document integration payloads**: Clearly communicate mandatory vs optional variable requirements across development teams.
