## What are Denoising Modes?

Denoising modes govern how aggressively Tavly preprocesses raw audio before sending it to the speech recognition (ASR) engine. This helps maintain transcription accuracy in challenging acoustic environments.

<img src="https://mintcdn.com/retellai/p4lyBmljCv__zWJl/images/denoising-mode.png?fit=max&auto=format&n=p4lyBmljCv__zWJl&q=85&s=7703a3d0b0f42e5825618f4db5e4c430" width="630" height="272" data-path="images/denoising-mode.png" />

* **No denoising:** Disables all audio preprocessing. Use this if you notice the agent dropping short affirmative responses (e.g., "yes", "sure") or suffering degraded accuracy on non-English transcriptions in otherwise quiet environments.
* **Remove noise (Default):** Strips ambient background noise with virtually zero distortion to the core audio waveform. This has no negative impact on ASR accuracy, but it will not filter out loud background speech.
* **Remove noise + background speech:** An aggressive filter utilizing Background Voice Cancellation (BVC) to isolate a single speaker. This costs an additional **$0.005/min**, distorts the waveform, and carries significant accuracy risks if misapplied.

<Warning> **Call Screening Conflict:** Never use "Remove noise + background speech" if you have call screening enabled. The system locks onto the first voice it hears—the automated screening prompt—and will permanently treat the actual live caller as background noise, suppressing their voice entirely.</Warning>

## When should you use aggressive Background Voice Cancellation (BVC)?

You should only enable **Remove noise + background speech** if your primary use case involves extremely loud, ongoing background speech (e.g., a bustling construction site or loud television) where the main caller remains clearly dominant.

<Note> **The Dominant Speaker Rule:** The BVC model strictly preserves only the loudest voice near the microphone. If the target user speaks quietly, or is far from the microphone relative to ambient voices, the model will classify the user as noise and delete their audio.</Note>

Because this model aggressively reshapes the raw audio waveform, applying it incorrectly will cripple transcription accuracy.

**Avoid BVC in these scenarios:**
* **No clearly dominant speaker:** (e.g., speakerphone in a shared room, handoffs between speakers). The model will randomly jump between voices or drop both.
* **Far-field microphones:** If the user is physically distant from the microphone while background voices are closer, the user is suppressed.
* **Clean audio environments:** Processing already-clean audio artificially distorts the waveform, actively lowering ASR accuracy and dropping short utterances for zero benefit.
* **Machine-generated audio:** The model is strictly tuned for human voices. It will mangle IVR prompts, hold music, and automated voicemail greetings.

## How do you tune Interruption Sensitivity?

Interruption Sensitivity controls how easily the agent stops speaking when it hears inbound audio. Lowering this value hardens the agent against false interruptions caused by ambient noise.

While denoising handles raw audio, loud background sounds can still trigger the agent to falsely interpret an interruption.

1. Navigate to the agent settings panel.
2. Set **Interruption Sensitivity** to a lower baseline, such as **0.8**.
3. Test the agent. This forces the system to require a stronger, clearer vocal signal before halting the agent's response.

**The Trade-off:** Lowering this value makes the agent highly resistant to background noise, but simultaneously requires the actual caller to speak louder and more forcefully to genuinely interrupt the agent.

## How can you reduce noise on the caller's side?

Because processing can only do so much, the most effective noise reduction strategy is improving the physical acoustic environment at the caller's origin.

* **Client-Side Noise Reduction:** If you are building a web-call interface, implement client-side noise reduction libraries before the audio stream ever hits Tavly's servers.
* **Agent Prompting:** Instruct the LLM within your global prompt to explicitly ask the caller to speak up or move to a quieter area if the agent detects it is repeatedly failing to transcribe input.
