## When should you use a Multilingual Agent?

Deploy a multilingual agent strictly when your callers might speak diverse languages and you cannot detect their language before the call connects. 

If you *can* determine a caller's language via CRM context or the dialed phone number, you will achieve significantly higher accuracy by deploying single-language agents and dynamically routing calls via the [inbound call webhook](/features/inbound-call-webhook).

## How do you configure multiple languages?

You explicitly select the exact dialects your agent must support by switching the dashboard's language selector to **Multiselect**.

In the dashboard, toggle to **Multiselect** and cherry-pick the necessary languages (e.g., English (US) and Spanish (Spain)).

**During a live call, the agent dynamically manages:**
* **Speech recognition:** The agent automatically calculates which of your selected languages the caller is speaking and transcribes it.
* **Voice pronunciation:** The agent analyzes the language of its own generated response and applies matching pronunciation rules. If detection fails, it falls back to your primary selected language.
* **Response Generation:** The agent seamlessly responds in any selected language based on the caller's input and your global prompt instructions.

## What are the accuracy trade-offs?

Using multiple language families routes the call through a heavier multilingual recognition pipeline, which inherently reduces accuracy compared to dedicated single-language models.

<Note> **Base Language Variants:** Selecting multiple variants of the same base language (e.g., `en-US` and `en-GB`) does **not** trigger the heavy multilingual pipeline. The agent stays on the highly accurate single-language path.</Note>

**Accuracy Ranking (Highest to Lowest):**
1. **Single Language:** The most accurate configuration. Use this whenever possible.
2. **Multiple Variants (Same Base):** No accuracy loss compared to single-language.
3. **Multiple Languages (Different Families):** Routes through the complex multilingual pipeline, incurring accuracy loss per language.
4. **Legacy Multilingual Setting:** A deprecated setting that blindly enables 10 specific languages.

## How do you handle closely related languages?

Speech recognition explicitly struggles to differentiate languages that share vocabulary, phonemes, or writing systems—such as Cantonese versus Mandarin Chinese.

Relying on auto-detection for these combinations frequently results in improper transcriptions and the agent responding in the wrong language entirely.

**Best Practices for Related Dialects:**
* **Force Single-Language Agents:** Route callers to dedicated agents or override the language per call via the [inbound call webhook](/features/inbound-call-webhook).
* **Never Rely on Auto-Detect:** Multilingual agents covering both Cantonese and Mandarin will confuse the two regardless of the underlying ASR provider.
* **Verify Provider Support:** Check the dashboard picker to ensure your ASR provider natively supports complex mixes (e.g., Cantonese + English). Review [Language support by provider](/build/language-support).

## What is the Legacy Multilingual Setting?

The legacy "Multilingual" toggle is a deprecated setting that globally enables exactly 10 hardcoded languages. It remains active only so older agents do not break.

## Why are some language combinations blocked?

The Tavly dashboard actively blocks you from selecting impossible language combinations based on dynamic provider capabilities.

* **Voice Limitations:** The specific TTS voice model you chose simply does not support the selected language. Switching to a different voice can unlock it.
* **ASR Limitations:** No single speech-recognition provider covers your exact combination of languages simultaneously. You must drop a language or split the logic across multiple agents.
