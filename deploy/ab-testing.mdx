A/B testing lets you compare multiple agents or scripts by sending a percentage of traffic to each. You define a traffic split (for example, 80% to one agent and 20% to another) so you can test different prompts, voices, or flows without changing your main agent.

## What is A/B testing?

**A/B testing** in Tavly allows teams to split conversational traffic across multiple agent variants or scripts using configurable percentage allocations. By routing live interactions (such as an 80/20 split) between different agent configurations, developers can empirically evaluate prompt wording, synthetic voices, and dialogue flows without replacing their core production agent.

Every A/B testing setup revolves around three operational pillars:

* **Multiple agents**: Bind or assign two or more agents to the same phone number or chat configuration.
* **Traffic split**: Set the percentage of traffic each agent receives (e.g., 80% / 20%). Traffic is distributed according to this split.
* **Empirical optimization**: Test different scripts on marketing or support calls, try prompt or voice changes, or compare conversation flows in chat.

## Where is A/B testing available across channels?

**A/B testing is available across four production channels**: inbound phone calls, outbound phone calls, inbound chat widgets, and outbound API chat sessions. Each channel allows teams to bind multiple agent configurations and establish percentage traffic splits to compare performance, latency, and resolution rates in live customer environments.

A/B testing is supported for:

* **Inbound calls** — Calls received on a phone number
* **Outbound calls** — Calls made from a phone number
* **Inbound chats** — Incoming chat conversations
* **Outbound chats** — Chat sessions you initiate

## How do you configure A/B testing on phone numbers?

To configure **A/B testing on phone numbers**, open your number in the Phone Numbers dashboard and enable the **A/B Testing toggle** next to Call Agent. Click **Edit** in the modal to add agent variants and assign percentage weights totaling 100%, then click **Deploy** to activate traffic distribution immediately.

On the phone number configuration page, the A/B Testing toggle appears next to the Call Agent field. Turn it on to bind multiple agents and set a traffic split. The screenshot below shows the control with A/B testing disabled:

## How do you view analytics and compare agent versions?

To view analytics by agent version, navigate to the **Analytics** dashboard, choose your experimental date range, and apply filters for the specific agents and versions tested. All dashboard charts will update dynamically, enabling direct comparison of call success rates, session durations, conversational latency, and completion metrics across experiment variants.

Follow these steps to analyze variant performance:

<Steps>
  <Step title="Open Analytics">
    Open **Analytics** in the Tavly dashboard.
  </Step>

  <Step title="Set date window">
    Set a date range that covers your experiment period.
  </Step>

  <Step title="Select Agent filter">
    In the filter bar, click **Agent** (or click **Filter** and add **Agent**).
  </Step>

  <Step title="Choose test agents">
    In the left panel, select the agent(s) used in your A/B test.
  </Step>

  <Step title="Designate target versions">
    In the right panel, select the specific version(s) you want to analyze (for example, `Version 3` vs `Version 4` of the same agent).
  </Step>

  <Step title="Apply and review charts">
    Click **Save** to apply the filter.
  </Step>
</Steps>

All charts on the page will update to the selected agent-version scope, so you can compare metrics (such as call success rate, duration, and latency) for each variant. For more details on Analytics, see [Get analytics insight](/monitor/analytics-dashboard).

## How does A/B testing compare to dynamic agent selection?

**A/B testing differs from dynamic agent selection** based on whether traffic routing is randomized or contextual. A/B testing applies a fixed statistical split (such as 50/50) without caller awareness, while dynamic agent selection routes calls or chats contextually using webhook logic, caller ID lookup, or custom runtime metadata.

<Tabs>
  <Tab title="A/B testing">
    Use when you want a **random percentage-based split**. Traffic is distributed according to the percentages you set, with no per-call or per-chat logic.
  </Tab>

  <Tab title="Dynamic selection (webhook / API)">
    Use when you want to **choose the agent per call or per chat** based on caller, context, or other data. For inbound calls, use the [Inbound Call Webhook](/deploy/inbound-call-webhook). For outbound calls or chats, pass the agent (or other overrides) in the API when you create the call or chat.
  </Tab>
</Tabs>
