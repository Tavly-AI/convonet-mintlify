## What is the Analytics Dashboard and when should you use it?

The **Tavly Analytics Dashboard** aggregates voice call and chat interaction data into visual reports, tracking key operational metrics including success rates, latency, concurrency, and spend over time. It allows engineering and operations teams to spot cross-session patterns, benchmark agent versions, evaluate financial costs, and correlate business outcomes alongside conversational volumes.

### Key Use Cases

* **Tracking Longitudinal Performance**: Monitor macro shifts in conversational success rates, average duration, or latency across days and weeks following system prompt updates or LLM model switches.
* **A/B Version Benchmarking**: Group metrics across agent versions to measure variance in user sentiment, resolution rates, and transfer percentages.
* **Financial Governance**: Monitor aggregate telephony and language model expenditures across agents and campaign days to forecast operational spend.
* **Correlating Business Outcomes**: Chart [custom Post-Call Extraction](/features/post-call-analysis-create) variables (e.g., appointment confirmations, qualified leads) directly against raw call volumes.

### Operational Boundaries

Analytics dashboards are purpose-built for multi-session aggregate analysis. To review granular conversational audio, inspect full debug transcripts, or analyze raw LLM payloads, navigate to [Call and Chat History](/features/session-history). To receive automated notifications when performance thresholds breach defined tolerances, configure [Alerting](/features/alerting-overview). To monitor in-flight calls as they happen, use [Live Monitoring](/features/live-monitoring).

## How do you create and manage dashboards?

To **create and manage dashboards**, open the overflow menu beside Add Chart, select Add Dashboard, and designate either Call or Chat scope. Each workspace supports up to **10 concurrent dashboards**. You can rename tabs, drag to reorder them, duplicate dashboards to test variations, and delete unneeded views.

<Steps>
  <Step title="Add the dashboard">
    Open the overflow menu next to **Add Chart**, choose **Add Dashboard**, and select either **Call** or **Chat**. The scope determines available metrics and cannot be altered once created.

## How do you add and configure a chart?

To **add and configure a chart**, click Add Chart, select your visualization style, pick your primary metric, and configure aggregation measurements. You can align time windows to dashboard defaults or set custom ranges, apply granular property filters, introduce up to five breakdown dimensions, and drag charts into customized row layouts.

<Steps>
  <Step title="Open the chart configuration drawer">
    Select **Add Chart** in the dashboard header.
  </Step>

  <Step title="Choose the graph visualization type">
    Designate your chart layout:
    * **Column**: Categorical comparisons across discrete time intervals or groupings.
    * **Bar**: Horizontal comparisons for categorical rankings.
    * **Line**: Continuous trend tracking over temporal horizons.
    * **Donut**: Proportional distribution across dimensions (such as disconnection reasons or sentiment).
    * **Number**: High-level executive KPI summary cards displaying a single aggregated metric.
  </Step>

  <Step title="Select metric and measurement function">
    Under **Call Source Metrics** (or **Chat Source Metrics**), choose a telemetry variable. Select the aggregation calculation: count metrics support **count**, while numerical metrics (such as duration, latency, and cost) support **avg**, **median**, **p90**, **sum**, **min**, and **max**. Click **+ Add** to plot multiple comparative metrics within a single chart.
  </Step>

  <Step title="Define time range, grouping, and comparison">
    Choose **Follow dashboard time range** to link with the global date picker, or specify an independent chart window. Select temporal aggregation intervals (**Hour**, **Day**, **Week**, **Month**). Enable **Previous period comparison** to plot an overlay of preceding period data.
  </Step>

  <Step title="Apply isolated filters and breakdowns">
    Optionally configure up to five dimensional breakdowns and granular filters scoped strictly to this visualization.
  </Step>

  <Step title="Save and arrange visualization">
    Click **Save**. The new chart appends to the bottom row of your dashboard, where you can reposition or resize it.
  </Step>
</Steps>

## What call and chat metrics can you chart?

Tavly provides specialized **call and chat source metrics** categorized by operational performance, telephony reliability, and conversational quality. Call dashboards track call counts, completion statuses, inbound versus outbound direction, disconnection reasons, user sentiment, durations, p50 end-to-end latency, peak concurrency, and total combined costs. Chat dashboards measure message counts, statuses, sentiment, and expenses.

### Available Call Metrics

| Metric | Supported Measurements | Telemetry & Operational Scope |
| :--- | :--- | :--- |
| **Call Counts** | `count` | Total quantity of initiated voice calls. |
| **Call Successful / Unsuccessful** | `count` | Voice sessions partitioned by post-call evaluation outcome. |
| **Call Status** | `count` | Calls segmented by operational state (e.g., registered, ongoing, ended). |
| **Phone Inbound / Outbound** | `count` | Total call volume divided by telephony stream direction. |
| **Disconnection Reason** | `count` | Distribution of termination triggers (e.g., user hung up, agent hung up, timeout). |
| **User Sentiment** | `count` | Calls classified by detected caller sentiment (Positive, Neutral, Negative). |
| **Call Successful Rate** | `avg` | Percentage of total calls meeting predefined evaluation success criteria. |
| **Call Picked Up Rate** | `avg` | Proportion of outbound attempts answered by a remote participant. |
| **Call Transfer Rate** | `avg` | Percentage of calls escalated to external telephone lines or human agents. |
| **Voicemail Rate** | `avg` | Share of outbound calls intercepted by [voicemail detection](/build/handle-voicemail). |
| **Call Duration** | `avg`, `median`, `p90`, `sum`, `min`, `max` | Total elapsed conversation duration in seconds. |
| **End to End Latency** | `avg`, `median`, `p90`, `min`, `max` | Round-trip p50 voice [latency](/reliability/check-actual-latency) aggregated across interactions. |
| **Concurrency Used** | `max` | Peak concurrent active call channels consumed against [concurrency limits](/deploy/concurrency). |
| **Combined Cost** | `avg`, `sum`, `median`, `p90`, `min`, `max` | Total monetary spend combining telephony carrier, LLM inference, and voice synthesis costs. |

### Available Chat Metrics

| Metric | Supported Measurements | Telemetry & Operational Scope |
| :--- | :--- | :--- |
| **Chat Counts** | `count` | Total number of digital chat sessions processed. |
| **Chat Successful / Unsuccessful** | `count` | Sessions partitioned by whether post-chat analysis verified successful resolution. |
| **Chat Status** | `count` | Chat interactions categorized by operational status. |
| **User Sentiment** | `count` | Chat interactions classified by post-session sentiment scoring. |
| **Chat Successful Rate** | `avg` | Proportion of chat sessions that met resolution targets. |
| **Combined Cost** | `avg`, `sum`, `median`, `p90`, `min`, `max` | Total cost of chat sessions, including LLM token consumption. |

## How do you configure time ranges, filters, and breakdowns?

To **configure time ranges, filters, and breakdowns**, use the top navigation controls to define analysis intervals, isolate specific agent criteria, and slice metrics across custom dimensions. The date picker supports calendar intervals and independent timezones, while filter panels combine base telemetry with post-call extraction variables and custom dynamic metadata.

### Global Date Range Picker

The header date picker applies to all charts configured to follow dashboard time:
* **Quick Presets**: Today, Last 7 days, Last 4 weeks, Last 3 months, Week to date, Month to date, Year to date, and All time.
* **Custom Calendar Range**: Set explicit start and end dates with independent start and end timezones to match operational business hours. Future dates are strictly disabled.

### Filtering Telemetry Data

Filters are organized into four functional categories:
1. **Base**: Native system parameters including agent ID, call ID, batch call ID, direction type, duration, from number, to number, user sentiment, disconnection reason, status, success flag, latency, and cost. A chat dashboard offers agent, chat ID, chat status, chat successful, combined cost, and user sentiment.
2. **Post-Call Extraction**: Custom structured extraction keys created via [Post-Call Analysis](/features/post-call-analysis-create).
3. **Metadata**: Custom key-value pairs attached during call initialization.
4. **Dynamic Variables**: Runtime variables populated during conversational agent flows.

Breakdowns partition chart series across distinct categorical values:
* **Call Dimensions**: Agent ID, agent version, disconnection reason, call status, call success status, call direction, and custom post-call extraction fields.
* **Chat Dimensions**: Agent ID, agent version, disconnection reason, chat status, chat success status, and post-chat extraction fields.

### Managing Unsaved Filter State & Grid Layout

When header filters or breakdowns are modified, the navigation bar enters an unsaved modification state displaying **Save** and **Cancel** buttons. Select **Save** to persist the filter configuration as default for future team visits, or **Cancel** to revert to the last saved dashboard state.

#### Customizing Grid Layout
* **Repositioning**: Drag charts within a row or across different rows. Each horizontal row accommodates up to **5 charts**.
* **Resizing Widths**: Drag vertical dividers between charts to reallocate horizontal space.
* **Resizing Heights**: Drag the lower handle of any row to adjust vertical height.
* **Creating New Rows**: Drag an existing chart below the current grid into empty space to instantiate a new row. Moving and resizing operations persist automatically without requiring manual saving.

### Role Permissions and Governance

Viewing and editing are governed as independent access levels. Users with view access can inspect dashboards, adjust session-specific filter views, and evaluate metrics. Creating new charts, adjusting global presets, or persisting layout configurations requires write permissions. See [Access Control](/accounts/access-control) for workspace permission assignments.

## Frequently Asked Questions

<AccordionGroup>
  <Accordion title="How fresh is the data in the Analytics Dashboard?">
    Charts read your workspace call and chat records directly upon interaction completion. Once a session ends and its post-call extraction pipeline finishes processing, the record is immediately indexed in dashboard queries without requiring manual cache invalidation or batch syncs.
  </Accordion>

  <Accordion title="Why does my chart display a 'too many data points' error?">
    A single chart visualization supports a rendering limit of **3,000 data points**. If your chart exceeds this threshold, narrow the time range, choose a coarser grouping unit (e.g., switch from Hour to Day or Week), or remove high-cardinality breakdown dimensions.
  </Accordion>

  <Accordion title="How can I inspect the individual call records behind a chart?">
    Click on any chart segment or expand its dimensional breakdown to view the corresponding subset parameters. To inspect the full conversational audio, transcripts, and telemetry for those sessions, open [Call and Chat History](/features/session-history) and apply matching filters.
  </Accordion>

  <Accordion title="Do individual chart filters override global dashboard filters?">
    No. Chart-level filters are merged with dashboard-level filters using logical AND semantics. For example, if the dashboard filters for calls from "Last 7 days" and a chart filters for a specific "Agent A", the visualization displays data exclusively for Agent A during the last 7 days.
  </Accordion>

  <Accordion title="Can a single dashboard display both call and chat metrics?">
    No. Channel scope (Call vs. Chat) is locked upon dashboard creation and cannot be modified. To analyze both channels, create two dedicated dashboards within your workspace (up to the 10 dashboard limit).
  </Accordion>

  <Accordion title="Is there a REST API endpoint to programmatically query dashboard charts?">
    Dashboard configurations are managed directly through the web UI. To extract raw interaction metrics and analysis fields programmatically, query the [List Calls API](/api-references/list-calls) and [List Chats API](/api-references/list-chats).
  </Accordion>
</AccordionGroup>
