## What is Post Call Extraction re-analysis and when should you use it?

**Post Call Extraction re-analysis** allows engineering teams to re-evaluate completed voice and chat transcripts using newly updated prompt instructions or revised success criteria. When business requirements or scoring logic evolve, rerunning analysis retroactively updates conversation summaries, sentiment classifications, and custom extracted schema fields across past historical interactions without requiring callers to redial.

### Essential Operational Constraints

<Note>
  **Draft Version Precedence**: Rerunning analysis on past conversations always executes against the analysis prompts configured in the **latest draft version** of your agent—even if the conversation originally ran against a previous published version. Always ensure updated prompts are saved in the current draft agent.
</Note>

<Note>
  **Transfer Leg Adherence**: If a conversation included an [Agent Transfer](/build/setup/single-multi-prompt/agent-transfer-tool), re-analysis preserves the original **Post Call Extraction setting** chosen for that transfer. If the transfer was set to **Only transferred agent**, the destination agent's full analysis configuration (analysis model, fields, and custom prompts) governs the rerun.
</Note>

<Warning>
  **Billing & Model Costs**: Rerunning analysis incurs processing charges for **all models**, including LLM tiers that may have been complimentary during initial post-call or post-chat processing.
</Warning>

## How do you customize call summary and success criteria prompts?

To **customize call summary and success criteria prompts**, open the agent Post-Call Data Extraction settings in the dashboard. Adjust the prompt guidelines powering `call_summary` to enforce specific brevity or detail constraints, and customize the prompt logic for `call_successful` to establish strict operational benchmarks. Changes save immediately to the agent draft version.

## How do you rerun analysis on an individual completed session?

To **rerun analysis on an individual session**, open the call details view in Call History, click Rerun Analysis, and confirm the execution modal. Tavly re-evaluates the full transcript against the prompt configuration saved in your agent latest draft version, updates the structured `call_analysis` object, and displays newly regenerated outputs instantly.

## How do you execute batch backfills across historical call archives?

To **execute batch backfills across historical archives**, navigate to Call History, click the Actions menu, and select Backfill from Post-Call Data. Define filtering parameters to isolate target date ranges, campaigns, or agents, then confirm execution. Tavly queues the re-extraction across all matching records and syncs updated data to mapped CRM fields.

<Steps>
  <Step title="Open the Actions menu">
    Navigate to the [Call History or Chat History](/features/session-history) page and click the **Actions** button located in the upper-right control bar.
  </Step>

  <Step title="Select Backfill from Post-Call Data">
    Choose **Backfill from Post-Call Data** (or **Backfill from Post-Chat Data** on the Chat History console) from the dropdown list.
  </Step>

  <Step title="Configure query filters">
    In the backfill configuration modal, define granular criteria to scope the backfill. Add filter rows to isolate specific agent IDs, date intervals, disconnection reasons, or existing analysis tags. Click **+ Add** to append multiple filtering rows.
  </Step>

  <Step title="Initiate the backfill job">
    Select **Save** to enqueue the batch extraction job. Tavly processes matching transcripts asynchronously using the latest draft agent configuration.
  </Step>
</Steps>

### Downstream CRM Synchronization

If your workspace utilizes [CRM Integrations](/integrations/crm/crm-integrations) (e.g., Salesforce, HubSpot), backfilled extraction fields automatically flow through configured [Analysis Data Mappings](/integrations/crm/crm-data-mappings) to update associated lead and contact properties.

## Frequently Asked Questions

<AccordionGroup>
  <Accordion title="Which agent version prompts are used when rerunning analysis on historical calls?">
    Tavly always evaluates reruns using the analysis prompts defined in the **latest draft version** of the agent, even if the historical call was originally processed by an older published version.
  </Accordion>

  <Accordion title="Are there additional billing charges associated with rerunning call analysis?">
    Yes. Rerunning post-call or post-chat analysis incurs LLM token charges across all models, including models that were initially free during the live conversation.
  </Accordion>

  <Accordion title="How does rerunning analysis handle calls involving multi-agent transfers?">
    Reruns adhere strictly to the Post Call Extraction setting configured on the transfer. If set to **Only transferred agent**, the destination agent's complete analysis configuration (model, fields, and prompts) is applied.
  </Accordion>

  <Accordion title="Does batch backfilling update connected CRM fields automatically?">
    Yes. If CRM integration is configured, regenerated extraction parameters automatically flow through your configured field mappings to update corresponding contact records.
  </Accordion>
</AccordionGroup>
